# 앱 출시 갈래 설계 — 커들마켓 안드로이드 1.0

> 작성일: 2026-07-30
> 대상: 6바퀴(출시 갈래 뚫기)와 그 뒤 1.0까지의 순서
> 앞 문서: `docs/session-logs/2026-07-29-handoff.md` (5바퀴까지의 상태)

---

## 1. 목적이 하나 더해졌다

지금까지 RN 앱의 목적은 **"채용 공고 대응을 위한 학습"** 이었다. 그래서 얇은 슬라이스로 화면을 하나씩 늘려 왔다.

이번에 목적이 **바뀐 게 아니라 하나 더해졌다.** 학습은 그대로 두고, 거기에 **실제 출시**가 붙었다.

```
  목적 ①  학습 · 설명 가능성   (그대로 유지)
  목적 ②  구글 플레이 정식 출시  (새로 더해짐)
```

**그래서 판단 기준이 둘이 된다.** 하나만 보면 안 된다.

| 기준 | 묻는 것 | 이 기준이 결정한 것 |
|---|---|---|
| 출시 | "출시 가능한 최소 앱이 무엇인가" | 지도·푸시·내 활동을 1.0에서 뺀 것 |
| 학습 | "설명할 이야기가 남는가" | 채팅을 1.0에 넣은 것 (STOMP 실시간이 이 로드맵에서 설명거리가 가장 많다) |

두 기준이 부딪히면 **출시를 막는 쪽이 이긴다.** 출시는 시계(테스터 12명 × 14일)가 걸려 있어 되돌리기 어렵지만, 학습은 1.1에서도 이어갈 수 있기 때문이다.

## 2. 목표와 범위

### 목표

- 커들마켓 안드로이드 앱을 구글 플레이에 **정식 출시**한다.
- 그 과정에서 **앱 배포·스토어 심사·실시간 통신**을 직접 겪어 설명할 수 있게 된다.
- iOS는 하지 않는다. (계정 비용 연 $99, 심사 반려 왕복, 실기기 없음)

### 출시 1.0에 넣는 것

| 기능 | 상태 |
|---|---|
| 로그인 · 상품 목록 · 상세 · 찜 | ✅ 이미 있음 (1~4바퀴) |
| 마이 목록 3종 + 거래 상태 변경·삭제·필터 | ✅ 이미 있음 (5바퀴) |
| 상품 등록 · 수정 | 7바퀴 |
| 커뮤니티 읽기 + 댓글 | 8바퀴 |
| 알림 목록 | 8바퀴 |
| 채팅 | 9바퀴 |

### 출시 1.0에서 빼는 것

| 뺀 것 | 이유 |
|---|---|
| **푸시 알림** | 백엔드에 푸시 토큰 저장 구조가 **전혀 없음**(전체 검색 0건). 토큰 API·발송 구현체·파이어베이스 설정이 모두 신규. 1.1로 |
| **지도** | 중고거래 핵심 고리 밖(동물병원·카페 등 **장소 찾기** 기능). 네이버 지도 API 키 발급이 별도로 붙음 |
| **커뮤니티 글쓰기** | 이미지 업로드가 딸려오는데, 그건 **상품 등록에서 먼저 뚫는 게 순서**. 한 번 뚫으면 커뮤니티가 그대로 재사용 |
| **내 활동 (내 글·내 댓글)** | 백엔드 API가 **없음**. 웹조차 빈 화면을 그리고 있어 "웹엔 있는데 앱엔 없다" 문제도 안 생김 |

## 3. 순서를 이렇게 잡은 이유

```
6바퀴  출시 갈래 뚫기     app.json · 아이콘 · eas.json · 첫 빌드 · 비공개 테스트 트랙
       └──▶ ⏱ 테스터 12명 × 14일 시계 시작
       └──▶ 개발 빌드 확보 = Expo Go 제약 해제

7바퀴  상품 등록 · 수정   첫 이미지 업로드를 여기서 뚫음
8바퀴  커뮤니티 읽기 + 알림 목록   둘 다 가벼워 한 바퀴에 묶임
9바퀴  채팅              가장 큼. 몸이 풀린 뒤에

──────── 여기까지 1.0 ────────
1.1    푸시 알림 · 커뮤니티 글쓰기 · 지도
```

**출시 갈래를 맨 앞에 두는 이유가 핵심이다.**

새로 만든 개인 개발자 계정은 프로덕션 출시 전에 **테스터 12명이 14일 연속** 비공개 테스트에 참여해야 한다. 이 14일은 내가 줄일 수 없다. 그러니 **기능이 다 끝난 뒤에 시작하면 출시가 3주 밀린다.**

지금 있는 기능만으로도 비공개 테스트는 시작할 수 있다. 시계를 먼저 돌려놓고 그 위에 기능을 얹으면, 같은 노력으로 출시가 3주 당겨진다.

## 4. 6바퀴 설계

### 4-1. 앱 정체성

`mobile/app.json`을 Expo 템플릿 기본값에서 실제 서비스 값으로 바꾼다.

| 항목 | 지금 | 바꿀 값 | 되돌리기 |
|---|---|---|---|
| `name` | `"mobile"` | `"커들마켓"` | 가능 |
| `slug` | `"mobile"` | `"cuddle-market"` | 가능 |
| `scheme` | `"mobile"` | `"cuddlemarket"` | 가능 |
| `android.package` | 없음 | **`com.cuddlemarket.app`** | ⚠️ **불가** |
| `android.versionCode` | 없음 | `1` (EAS 자동 증가) | — |

이름을 **한글 「커들마켓」** 으로 하는 근거: 웹이 이미 그렇게 부른다(`src/app/layout.tsx:14` `title: '커들마켓'`). 그리고 홈 화면 아이콘 밑에서 `Cuddle Market`(13자)은 잘리지만 `커들마켓`(4자)은 안 잘린다.

식별자는 **Play Console에 처음 올리는 순간부터 영구 고정**된다. 그 전까지는 빌드해서 폰에 깔아봐도 잠기지 않는다.

### 4-2. 아이콘 · 스플래시

**웹 자산을 그대로 가져온다.** 새로 디자인하지 않는다.

| 앱 파일 | 재료 |
|---|---|
| `icon.png` | `public/android-chrome-512x512.png` → 1024×1024로 키움 |
| `android-icon-foreground.png` | `public/android-chrome-maskable-512x512.png` |
| 적응형 아이콘 배경색 | `#FF6F0F` (웹 `manifest.json`의 `theme_color`) |
| 스플래시 배경 | `#ffffff` (웹 `manifest.json`의 `background_color`) |

512를 1024로 키우면 흐려질 수 있다. **실기기에서 눈으로 확인하고, 흐리면 그때 다시 만든다.** 원본 로고(`CuddleMarketLogoImage_v2.png`)는 826×357로 가로가 길어 정사각 아이콘에 바로 못 쓴다.

앱 안쪽 색(`constants/theme.ts`의 `#0a7ea4`)은 **건드리지 않는다.** 이슈 #786(앱 색 토큰 체계)의 범위다.

### 4-3. 빌드 구성

`mobile/eas.json`을 새로 만든다. 프로필은 **둘이면 충분하다.**

| 프로필 | 산출물 | 쓰임 |
|---|---|---|
| `preview` | APK | 내 폰에 직접 설치해 "진짜 앱"으로 확인 |
| `production` | AAB | 구글 플레이에 올리는 것 |

**개발용(dev client) 프로필은 만들지 않는다.** 1.0 범위 기능이 전부 Expo Go에서 개발되기 때문이다.

- 상품 등록의 사진 선택 → `expo-image-picker`는 Expo Go 지원
- 채팅 → 순수 WebSocket, RN 내장
- 커뮤니티 · 알림 목록 → REST

Expo Go에서 안 되는 건 **푸시 알림 하나뿐**이고 그건 1.1이다. 그때 필요한 일을 지금 당겨 할 이유가 없다.

### 4-4. 테스트 트랙

**「비공개 테스트(closed testing)」 트랙을 쓴다.** 내부 테스트는 12명 요건에 **안 센다.**

> *"프로덕션 액세스 권한을 신청하려면 12명 이상의 테스터가 **비공개 테스트**에 참여하겠다고 선택해야 합니다."* (Play Console 고객센터)

여기서 트랙을 잘못 고르면 14일을 통째로 날린다.

### 4-5. 법적 준비물 — 개인정보처리방침

**구글 플레이는 개인정보를 수집하는 앱에 개인정보처리방침 URL을 요구한다.** 커들마켓은 로그인이 있으므로 해당한다. 웹에 페이지가 **하나도 없어서** 만들어야 한다.

- 초안: `docs/privacy-policy-draft.md` (작성 완료)
- 근거: 개인정보 보호법 제30조, **2026 개인정보 처리방침 작성지침**(개인정보보호위원회) 23개 기재사항으로 대조
- 웹에 `/privacy` 페이지로 배포해 URL 확보

**이용약관은 1.0 범위 밖이다.** 플레이 제출에 필수가 아니다. 다만 이용자끼리 거래하는 서비스라 나중에 갖추는 편이 좋다.

### 4-6. 백엔드 수정 2건 — 방침을 사실로 만들기

방침을 쓰다가 **코드가 방침과 어긋나는 곳 둘**을 찾았다. 지침이 가장 강조하는 원칙이 "방침과 실제 처리 현황이 일치해야 한다"이므로, 방침을 공개하기 전에 코드를 고쳐야 한다.

| # | 문제 | 근거 | 고칠 방향 |
|---|---|---|---|
| 1 | **탈퇴해도 개인정보가 안 지워짐** | `User.java:129` `softDelete()`가 `deletedAt`에 날짜만 찍음. 나중에 지우는 배치도 없음 | 아래 표의 필드를 비운다 |
| 2 | **소셜 가입·프로필 수정에 나이 검사가 없음** | `validateAge`는 백엔드 전체에서 **`AuthServiceImpl.signUp:76` 한 곳에서만** 호출된다. 소셜 가입 완료와 프로필 수정은 둘 다 `PATCH /profile/me`를 쓰는데 거기엔 검사가 없다 | `ProfileServiceImpl.updateProfile`(`:71`)의 닉네임 검증 다음에 같은 검사를 넣는다. **한 곳을 고치면 구멍 둘이 함께 막힌다** |

> 처음에는 "만 14세 검사가 아예 없다"고 판단했으나 **틀렸다.** 검색 범위를 `web/user/`로 좁게 잡은 탓이었고, 실제 로직은 `cmarket-domain/auth/`에 있었다. 이메일 가입은 이미 막고 있다. 남은 구멍은 위 표의 한 곳이다.
>
> 덧붙여, 생년월일을 스스로 적게 하는 나이 확인은 **원래 약한 장치**다. 나이를 속여 적으면 막을 수 없다. 법이 요구하는 것도 완벽한 차단이 아니라 합리적인 노력이므로, 구멍을 막되 이것이 완전한 장치는 아님을 알고 간다.

**탈퇴 시 각 필드를 어떻게 할지** (1번의 세부):

| 필드 | 처리 | 왜 |
|---|---|---|
| `email` | 비움 또는 알아볼 수 없는 값으로 | 고유 제약이 걸려 있어 그냥 `null`로 두면 여러 명이 겹칠 수 있다. 실제 처리 방식은 구현 때 정한다 |
| `password`, `name`, `birthDate`, `addressSido`, `addressGugun`, `profileImageUrl`, `introduction`, `socialId` | 비움 | 회원을 알아볼 수 있는 정보 |
| `nickname` | 비움 또는 알아볼 수 없는 값으로 | 고유 제약. `email`과 같은 문제 |
| `deletedAt`, `withdrawalReason`, `withdrawalDetailReason` | **남김** | `UserRepository.java:84`가 탈퇴 사유를 집계한다. 이걸 지우면 통계가 깨진다 |
| `id`, `createdAt` | 남김 | 게시글·상품의 작성자 연결이 끊기지 않게 |

⚠️ 이미 탈퇴한 기존 회원의 정보도 남아 있다. **한 번 정리하는 작업이 필요한지** 구현 때 확인한다.

### 4-7. 6바퀴 완료 기준

```
  1. app.json이 커들마켓 값으로 바뀜
  2. 아이콘 · 스플래시가 웹 것으로 교체됨
  3. eas.json으로 preview APK가 빌드됨
  4. 그 APK가 실기기에 Expo Go 없이 설치되고, 로그인 · 목록 · 상세가 동작
  5. 백엔드 2건 수정 + 배포
  6. 웹에 /privacy 페이지 배포 → URL 확보
  7. production AAB가 비공개 테스트 트랙에 올라감
  8. 테스터 12명이 링크로 설치 → ⏱ 14일 시계 시작
```

7·8번은 **구글의 본인 확인이 끝나야** 가능하다. 그때까지 1~6번을 해둔다.

## 5. 하지 않는 것

과설계를 막기 위해 명시한다.

- **dev client 프로필** — 1.0 기능이 Expo Go에서 다 된다. 푸시(1.1) 때 만든다
- **앱 안쪽 색 토큰 정리** — 이슈 #786의 범위
- **SDK 업그레이드** — 개발 빌드로 넘어가면 SDK 54 족쇄가 풀리지만, 지금 올릴 이유가 없다
- **이용약관** — 플레이 제출에 필수가 아니다
- **스토어 스크린샷 자동화** — 손으로 몇 장 찍으면 된다
- **CI에서 EAS 빌드 자동 실행** — 빌드 횟수가 적다. 손으로 돌린다

## 6. 조사로 확정된 사실 (다음 바퀴에서 재사용)

7~9바퀴 계획을 세울 때 다시 조사하지 않도록 남긴다. **모두 실제 파일·실서버로 확인한 것이다.**

### 상품 등록 (7바퀴)

- 백엔드 있음: `POST /api/products`, `PATCH /api/products/{id}`
- 이미지 업로드: `POST /api/images` multipart `files`, **최대 5장 · 장당 5MB** (`ImageController.java:56`)
- 앱에 업로드 코드 **0줄**. 이게 앱의 첫 업로드가 된다
- ⚠️ 업로드 응답 모양이 웹 타입과 어긋나 보인다 — 붙일 때 실측 필요

### 커뮤니티 (8바퀴)

- 백엔드 **9개 완비** (`CommunityController.java`): 목록·상세·작성·수정·삭제·댓글목록·댓글작성·대댓글목록·댓글삭제
- **마크다운 라이브러리가 필요 없다.** 실서버 게시글 30건을 받아 확인한 결과, 쓰이는 문법은 **줄바꿈과 `![이미지](url)` 둘뿐**. 굵게·제목·목록·링크는 0건
- 상세 응답의 `imageUrls` 필드는 **비어 있다**(본문에 이미지가 셋인 글도 `[]`). 무시하면 된다
- 없는 기능: 좋아요, 댓글 수정, 댓글 신고
- 새 화면 2개(목록·상세)면 된다. 기존 무한스크롤·3상태·시트·삭제확인창을 그대로 쓴다

### 알림 목록 (8바퀴)

- 백엔드 REST **4개 완비**: `GET /api/notifications`, `/unread-count`, `PATCH /{id}/read`, `/read-all`
- 웹 목록 화면은 GraphQL을 거치지만 **앱은 REST를 직접 부르면 된다**
- SSE는 필요 없다. 앱 진입·포그라운드 복귀 때 다시 조회하면 충분

### 채팅 (9바퀴)

- **백엔드를 한 줄도 안 고쳐도 된다.** 실서버로 확인:
  - `GET /ws-stomp/info` → `{"websocket":true}`
  - `/ws-stomp/websocket`에 WebSocket 업그레이드 요청 → **101 Switching Protocols**
- 웹은 `sockjs-client`를 쓰는데 **RN에서는 못 쓴다**(`document`에 의존). 대신 `@stomp/stompjs`로 `wss://cmarket-api.duckdns.org/ws-stomp/websocket`에 직접 붙는다
- 인증은 웹과 같다 — STOMP 접속 헤더에 `Authorization: Bearer`
- ⚠️ **Origin 지뢰**: 서버가 Origin을 검사한다. 실측 결과

  | 보낸 Origin | 응답 |
  |---|---|
  | 없음 | 101 ✅ |
  | `https://cmarket-api.duckdns.org` (RN이 자동으로 넣는 값) | 101 ✅ |
  | `exp://192.168.0.10:8081` | **403** ❌ |
  | `http://localhost:8081` | **403** ❌ |

  RN은 주소에서 Origin을 만들어 붙이므로 **그냥 두면 통과하고, 손대면 깨진다.** `headers: { origin: ... }`을 직접 넣지 말 것
- 새 채팅 메시지가 오면 서버가 **알림 기록을 남긴다**(`ChatServiceImpl.java:341` `CHAT_NEW_MESSAGE`). 그래서 푸시가 없어도 앱을 켜면 "새 메시지 있음"을 알 수 있다
- ⚠️ 필드 어긋남: WebSocket 응답엔 `chatRoomId`가 있고 `isMine`이 없다 / REST 이력엔 `isMine`이 있고 `chatRoomId`가 없다 → 앱에서 `senderId == 내 id`로 계산해야 한다

## 7. 알려진 함정

| 함정 | 대처 |
|---|---|
| **EAS Build는 `.env`를 안 올린다** (gitignore라서) | `eas env:set`으로 EAS에 등록. 빌드 로그의 `No environment variables ... found` 경고가 신호 |
| **Expo Go에서 되는 게 독립 빌드에서 된다는 뜻이 아니다** | Expo Go는 Metro가 번들을 주고, 독립 빌드는 EAS 서버가 `pnpm install`을 새로 돌려 만든다. **모듈 배치가 달라질 수 있다** |
| **EAS 빌드 번들에 react가 두 벌 들어가 앱이 켜자마자 죽었다** | `metro.config.js`의 `resolveRequest`로 `react`·`react-dom`을 mobile 것 한 벌로 고정. 웹(Next 16)이 19.2.3, mobile(RN 0.81)이 19.1.0을 쓰는데 EAS 서버는 `pnpm install`을 새로 돌려 둘 다 번들에 넣었다 |
| **APK 안을 직접 뜯어보기 전엔 못 찾는다** | `unzip -o apk "assets/index.android.bundle"` → `strings -a ... \| grep -oE "19\.[0-9]+\.[0-9]+"`. 코드를 읽고 세운 가설 둘(환경변수·reactCompiler)은 **둘 다 틀렸다** |
| **앱이 켜자마자 죽으면 추측하지 말고 `adb logcat`** | 무선 디버깅으로 USB 없이 된다. `adb pair` → `adb logcat -d \| grep ReactNativeJS`. 추측으로 20분짜리 빌드를 반복하는 것보다 5분이 빠르다 |
| `android.package`는 첫 업로드 후 영구 고정 | 빌드해서 폰에 깔아보고 확정. 올리기 전엔 자유롭게 바꿀 수 있다 |
| 내부 테스트는 12명 요건에 안 셈 | **비공개 테스트** 트랙을 쓴다 |
| 개인정보처리방침 없으면 트랙 업로드에서 막힘 | 6바퀴에 포함 |
| 방침과 코드가 어긋나면 그 자체로 문제 | 백엔드 2건을 먼저 고친 뒤 방침 공개 |
| 전화번호 인증은 본인 확인이 끝나야 열림 | 잊지 말고 다시 들어가서 처리 |
| 신분증은 **가리거나 수정하면 반려** | 원본 그대로 올린다 |
| 테스터 12명은 **전부 안드로이드** 사용자여야 함 | 아이폰 쓰는 사람은 안 셈 |
