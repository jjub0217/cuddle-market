# 앱 커뮤니티 글쓰기 설계 (#915 · 23바퀴)

> 2026-08-13(목). 앱에서 커뮤니티 글을 **쓸 수** 있게 한다. 지금은 읽기와 댓글만 된다.

## 왜 지금인가

앱 커뮤니티는 10바퀴에 **읽기 + 댓글**까지만 만들었다. 그래서 앱만 쓰는 사람은 글을 못 쓴다 —
질문이 있어도 웹 브라우저로 나가야 한다. 사진 올리기는 상품 등록에서 이미 뚫어 놓았으므로
지금이 붙이기 좋은 때다.

## 이미 확인한 것 (다시 조사하지 말 것)

### 서버가 받는 값

`POST /api/community/posts` · `PostCreateRequest.java`

```
title       2~50자    필수
content     2~1000자  필수
imageUrls   최대 5장   ⚠️ 웹은 늘 빈 배열로 보낸다. 서버도 목록 썸네일에 안 쓴다
boardType   QUESTION | INFO   필수
```

### ⚠️ 목록 썸네일은 **본문에서 뽑는다**

`PostListItemResponse.java:63`

```java
private static String extractThumbnailImageUrl(String content) {
    Matcher matcher = MARKDOWN_IMAGE_PATTERN.matcher(content);
    return matcher.find() ? matcher.group(1) : null;   // 본문 첫 ![](주소)
}
```

**그래서 사진을 본문 마크다운에 안 넣으면 목록에 썸네일이 안 생긴다.** `imageUrls` 에 넣어도
소용없다. 이 사실이 아래 설계를 결정했다.

### 웹은 어떻게 하고 있나

```
글쓰기 진입   모바일 폭에서 오른쪽 아래 뜬 단추 「＋ 글쓰기」 (CommunityPage.tsx:365)
             지금 보고 있는 게시판을 ?tab= 으로 들고 간다
사진         마크다운 편집기가 커서 자리에 ![](주소) 를 끼워 넣는다
imageUrls    폼에 있지만 **한 번도 안 채운다**(늘 [])
```

## 범위

### 만든다

```
글쓰기 화면        제목 · 본문 · 게시판 고르기 · 사진 최대 5장
목록의 글쓰기 단추   웹 모바일과 같은 자리·같은 문구
사진 올리기        상품 등록의 것을 그대로 쓴다(POST /api/images)
```

### 안 만든다

```
마크다운 편집기       폰에서 굵게·목록 단추까지 만들 일이 아니다
커서 자리에 사진 넣기   글 아래에 차례로 붙이는 것으로 갈음한다(아래)
글 수정·삭제         이번 범위 밖. 별도 이슈로 연다
임시 저장            웹에는 있지만(DraftModal) 이번엔 뺀다
```

## 사진을 본문에 넣는 방식 — 이 설계의 알맹이

사용자는 **글과 사진을 따로** 다루고, 보낼 때 **본문 끝에 사진 줄을 이어 붙인다.**

```
사용자가 보는 것              서버로 가는 content
────────────────────────    ──────────────────────────
제목: 캣타워 팔아요            (title 로 따로 간다)
본문: 상태 좋아요              상태 좋아요
사진: [A] [B]                 ![](A주소)
                              ![](B주소)
```

이렇게 하면 셋이 저절로 맞는다.

```
✅ 앱에서 쓴 글이 웹에서 똑같이 보인다 — 둘 다 마크다운을 그린다
✅ 목록 썸네일이 생긴다 — 서버가 본문 첫 사진을 뽑는다
✅ 앱에서 읽을 때도 그대로 보인다 — post-body.tsx 가 마크다운을 그린다
```

`imageUrls` 는 **빈 배열로 보낸다.** 웹도 그렇고 서버도 안 쓴다.

### ⚠️ 글자 수를 셀 때 사진 몫을 빼야 한다

서버 한계는 본문 **1000자**인데 `![](주소)` 한 줄이 100자 안팎이다. 사진 다섯이면 500자를 먹는다.

```
화면에 보여줄 남은 글자 = 1000 − (사진 줄들의 길이) − (지금 쓴 본문 길이)
```

이걸 안 하면 **「999자 썼는데 등록이 안 된다」** 가 난다. 서버 오류로만 알게 되는 종류다.

## 화면

`mobile/app/community-post.tsx` — **루트 화면**(탭 안이 아니다).

```
┌─────────────────────────────┐
│ ←  글쓰기              [등록] │  ScreenHeader
├─────────────────────────────┤
│ [질문 있어요] [정보 공유]      │  목록과 같은 알약(BOARD_CHIPS)
│                             │
│ 제목                         │  2~50자
│ ┌─────────────────────────┐ │
│ 내용                         │  2~1000자 (사진 몫을 뺀 남은 글자를 보여준다)
│ ┌─────────────────────────┐ │
│ │                         │ │
│ └─────────────────────────┘ │
│ 사진 (0/5)                   │
│ ┌──┐┌──┐┌──┐                │  상품 등록과 **같은 격자**
│ │＋││  ││  │                │  flexDirection:'row' + flexWrap:'wrap'
│ └──┘└──┘└──┘                │
└─────────────────────────────┘
```

⚠️ **루트 화면이라 `SafeAreaView` 에 `edges={['top','bottom']}` 를 준다.** 탭 화면과 다르다 —
아래에 탭바가 없어 기기 바를 자기가 비켜야 한다(`mobile/AGENTS.md`).

⚠️ **`KeyboardAvoidingView` 는 양쪽 다 `behavior="padding"`.** 안드로이드는 창이 안 줄어든다
(`edgeToEdgeEnabled: true`). 본문 칸과 사진 격자를 **함께** 감싸야 위쪽이 안 가려진다.

### 왜 캐러셀이 아니라 격자인가

상품 등록(`mobile/components/products/image-field.tsx:194`)이 이미 격자다.

```
① 같은 앱에서 사진 고르는 화면이 두 가지면 안 된다
② 캐러셀은 고를 때 불리하다 — 몇 장 골랐는지, 어느 걸 지울지 넘겨 봐야 안다
③ 이미 만들어져 있다 — 고르기·미리보기·올리는 중 표시·지우기·다시 시도가 다 들어 있다
```

**읽는 쪽(게시글 본문)은 세로로 이어진다.** 마크다운이라 그렇고 웹도 같다. 캐러셀로 바꾸려면
두 매체의 본문 그리는 방식을 다 바꿔야 해서 이번 범위가 아니다.

## 사진 칸을 어떻게 마련하나 — ㉮ 따로 만든다

`image-field.tsx` 에는 **대표 사진 지정**(`makeMain`)이 얽혀 있는데 커뮤니티에는 대표 개념이 없다.

```
㉮ 커뮤니티용을 따로 만든다   상품 등록을 안 건드린다. 비슷한 코드가 둘   ← 이걸 고른다
㉯ 공용으로 갈라낸다         대표 지정을 옵션으로. 상품 등록도 같이 고쳐야 한다(회귀 위험)
```

**㉮를 고른 이유** — 상품 등록은 잘 돌고 있고, 지금 건드리면 확인할 범위가 두 배가 된다.
세 번째 쓰는 곳이 생기면 그때 갈라내면 된다. 올리는 로직(`product-images.ts`)은 **그대로 쓴다** —
거기는 대표 개념이 없다.

```
새로 만든다   mobile/components/community/post-image-field.tsx   대표 지정 없는 격자
그대로 쓴다   mobile/lib/product-images.ts                      pickImages·shrinkImage·uploadOne
```
