# 앱 검색 · 필터 설계 (15바퀴)

> 2026-08-06 합의

## 1. 무엇을 만드나

**앱 홈에 조건이 하나도 없다.** 「전부 다 보기」뿐이라 원하는 걸 찾을 방법이 없다.

```
웹 홈   조건 12가지
앱 홈   GET /products/search?page=0&size=20    ← 페이지 번호뿐
```

찾는 길 둘을 만든다 — **검색어**와 **앞줄 필터**.

## 2. 핵심 결정 — 목록은 조각 하나다

이번 설계에서 가장 중요한 것. 나머지가 여기서 따라 나온다.

```
홈        상품 목록 (조건: 필터)
검색 결과   상품 목록 (조건: 필터 + 검색어)
```

**같은 것이다.** 조건 하나가 더 붙었을 뿐이다. 그래서 화면을 둘 만들되 **속은 같은 조각**을 쓴다.

```
components/products/product-list-view.tsx   ← 새로 뺀다
    필터 줄 · 목록 · 무한스크롤 · 로딩/오류/빈 화면

app/(tabs)/(home)/index.tsx     이 조각을 쓴다 (검색어 없음)
app/search-result.tsx           이 조각을 쓴다 (검색어 있음)
```

**왜 이렇게 하나** — 「결과 화면에도 필터가 필요한가」를 고민할 필요가 없어진다. 조각 안에 있으니 **저절로 양쪽에 생긴다.** 두 화면을 따로 만들면 나중에 필터를 넣을 때 **같은 코드를 두 번 짜게 된다.**

⚠️ 대신 **홈을 뜯는다.** 지금 홈은 조회부터 빈 화면 처리까지 화면 파일 안에 다 들어 있다. 앱에서 가장 중요한 화면이라 **빼내는 것만 먼저 하고 게이트를 돌린 뒤** 그 위에 얹는다(§7).

## 3. 화면 셋

```
① 홈 (탭)                    ② 검색 (밀려 나옴)         ③ 결과 (밀려 나옴)
┌──────────────┐          ┌──────────────┐        ┌──────────────┐
│ [로고]  🔍 ＋  │          │ ‹ [입력칸    ✕] │        │ ‹ 강아지 사료   │
│ 전체 포유류 조류…│          │               │        │ 전체 포유류 조류…│
│ 전체 사료 장난감…│          │  (최근 검색어는 │        │ 전체 사료 장난감…│
│ ─────────── │          │   다음 바퀴)    │        │ ─────────── │
│  목록         │          │               │        │  목록         │
└──────────────┘          └──────────────┘        └──────────────┘
```

**검색은 헤더의 돋보기로 연다.** 모바일 웹이 이미 그렇고(`Header.tsx:214`), 중고거래 앱의 관례이며(당근), 무엇보다 **알약 두 줄 때문에 세로가 빠듯하다.**

**결과는 별도 화면으로 민다.** 웹은 홈에 `?keyword=`를 붙이지만 앱은 화면 스택이 있다.

```
뒤로가기가 곧 「검색 취소」다 — 되돌리기를 따로 만들 필요가 없다
홈이 홈으로 남는다 — 골라둔 필터가 안 지워진다
지금 무슨 상태인지 헷갈릴 일이 없다
```

## 4. 이번에 거는 조건 셋

서버(`ProductSearchRequest`)는 12가지를 받는다. **그중 셋만 쓴다.**

```
keyword       검색어
petType       반려동물 **대분류** (9개)
categories    상품 카테고리 (8개) — 서버는 목록을 받지만 **하나만** 보낸다(웹과 같다)
```

**서버 작업이 0이다.** 앱이 이미 `/products/search`를 부르고 있으니 조건만 얹는다.

선택지는 **`@cuddle/shared`에 이미 있다** — `PET_TYPE_OPTIONS`(9) · `CATEGORY_OPTIONS`(8).
앱이 이미 그 꾸러미를 쓰고 있어 새로 만들 것이 없다.

**고르는 법은 웹과 같다** — 하나만 고르고, 같은 것을 다시 누르면 풀린다. 맨 앞에 「전체」를 둔다.

## 5. 웹과 갈리는 곳

| | 웹 | 앱 | 왜 |
| --- | --- | --- | --- |
| 검색 결과 자리 | 홈에 `?keyword=` | **별도 화면** | 웹은 주소가, 앱은 화면 스택이 자연스럽다 |
| 반려동물 상세 종류 | 있다(40개) | **없다** | 폰 한 줄에 40개는 안 들어간다. 다음 바퀴 |
| 세부 필터 | 단추로 연다(상태·가격·지역) | **없다** | 다음 바퀴 |

**같은 것**: 검색 문구(「원하는 반려동물 용품을 검색해보세요」), 앞줄 필터의 뜻과 순서, 하나만 고르고 다시 누르면 풀리는 방식, 서버 주소.

## 6. 이번에 안 하는 것

```
반려동물 상세 종류 40개   다음 바퀴 — 폰에 담는 방법을 따로 설계해야 한다
가격 · 지역 · 상태       다음 바퀴 — 「좁히는」 조건이지 「찾게 해주는」 조건이 아니다
정렬(최신·가격·찜)       다음 바퀴
최근 검색어             다음 바퀴 — 저장할 곳(기기)을 정해야 한다
커뮤니티 검색            웹에는 있다. 상품과 조각을 나눠 쓸 수 있는지 그때 본다
```

## 7. 단계 — 홈을 뜯는 순서

**홈은 앱에서 가장 중요한 화면이다.** 한 번에 다 바꾸면 어디서 깨졌는지 모른다.

```
1단계  홈의 목록을 조각으로 빼낸다        기능 변화 0. 게이트로 확인한다
2단계  그 조각에 필터 줄을 붙인다          홈에서 눈으로 확인한다
3단계  검색 화면 + 결과 화면              결과도 같은 조각을 쓴다
```

1단계에서 **눈에 보이는 변화가 없어야 한다.** 그게 확인 방법이다.

## 8. 미리 아는 함정

```
홈 회귀           조회·무한스크롤·찜·빈 화면·오류가 다 얽혀 있다.
                 빼낼 때 **하나도 안 바뀌어야** 한다. 시험이 지켜 준다

알약이 세로를 먹는다  두 줄이면 목록 시작점이 꽤 아래다.
                 실기기에서 「목록이 몇 개나 보이는지」 확인할 것

조건이 바뀌면 처음부터  필터를 바꿨는데 2페이지부터 이어 받으면 안 된다.
                 queryKey 에 조건을 넣어 **새 목록으로** 시작하게 한다

「전체」의 뜻        서버에 빈 값을 보내는 것이다. 'ALL' 같은 글자를 보내면 안 된다

검색어 없는 결과 화면  검색 화면에서 아무것도 안 치고 넘어가면 홈과 같아진다.
                 빈 검색어면 넘어가지 않는다

가로 스크롤 알약     9개·8개가 화면 밖으로 나간다. **잘린 게 보이게** 오른쪽 여백을 준다
                 (다 보이는 줄 알면 뒤에 더 있는 걸 모른다)
```

## 9. 완료 기준

- [ ] 홈에 반려동물 대분류·카테고리 알약이 두 줄로 있다
- [ ] 알약을 고르면 목록이 그 조건으로 바뀐다. 다시 누르면 풀린다
- [ ] 헤더의 돋보기를 누르면 검색 화면이 뜬다
- [ ] 검색어를 넣으면 결과 화면이 뜨고, 거기서도 알약을 쓸 수 있다
- [ ] 뒤로 가면 홈의 필터가 그대로 남아 있다
- [ ] `pnpm gate:mobile` 초록
- [ ] 실기기에서 홈이 **전과 똑같이** 동작한다 (1단계 회귀 확인)
