# 단추·입력칸 높이·색 설계 (#847)

> 웹과 앱의 공용 조각에서 높이가 화면마다 섞인 것을 한 방식으로 모은다.
> #786에서 넘어온 색 둘(입력칸 테두리·주 단추)도 여기서 함께 정한다.

## 1. 지금 어떤가 — 실측 (2026-08-09)

### 웹

```
Button
  xs   px-3 py-2 text-sm     36    1곳    ⚠️ sm 과 값이 똑같다
  sm   px-3 py-2 text-sm     36   43곳    가장 많이 쓰인다
  md   px-4 py-2 text-base   40   33곳 + size 안 준 곳
  lg   px-6 py-3 text-base   48    3곳

Input (text-sm 기준)
  모바일   py-2 → 8+20+테두리2 = 38
  데스크탑  py-3 → 24+20+2     = 46

InputWithButton
  입력칸   py-2 md:py-2.5 → 모바일 42 · 데스크탑 42
  단추     h-10 md:h-11   → 모바일 40 · 데스크탑 44
```

### 앱

19바퀴(#786)에 색·글자·테두리는 맞췄지만 **높이는 손대지 않았다.**

```
40   댓글 등록                             입력칸 옆에 붙어 있다
44   비밀번호 찾기 「다음」
46   확인 대화창 · 로그아웃 모달 「확인」       창 안이다
48   로그인 · 가입 · 소셜가입 · 신고
     · 상품등록 · 로그인폼                   ← 여섯 곳. 대세다
52   프로필 수정 「저장」                     ⚠️ 이유 없이 혼자 크다
```

## 2. 뿌리는 「방식이 갈린 것」이다

높이가 **각자 다른 방식으로 정해진다.**

```
padding + 줄높이   Input · Button      글자 크기를 바꾸면 높이가 따라 변한다
h-* 고정          InputWithButton 단추  글자 크기와 무관하게 고정
```

그래서 `text-sm`을 `text-base`로 바꾸면 어떤 것은 커지고 어떤 것은 안 커진다.
나란히 붙은 **인증코드 칸(42)과 재전송 단추(44)의 2px**이 그렇게 생겼다.

### 반응형 방향은 이미 맞다 — 다만 공용 조각에 안 심겼다

```
모바일   손가락으로 누른다   Apple HIG 44pt · Material 48dp 권장   → 커야 한다
데스크탑  마우스로 누른다     커서는 정확하다                       → 작아도 된다
```

⚠️ **공용 조각의 기본값은 반대로 되어 있다**(`py-2 md:py-3` — 데스크탑이 크다).
그래서 화면 셋이 손으로 덮어썼다.

```
✅ 덮어쓴 곳 (모바일에서 키움)
   login/LoginForm.tsx            inputClass="py-3" · py-3 md:py-2
   login/SocialLoginButtons.tsx   py-3 md:py-2
   find-password/FindPasswordForm.tsx   wrapperClassName="h-12" 네 곳

❌ 안 덮어쓴 곳 (기본값 그대로 = 모바일이 작다)
   가입 · 상품 등록 · 프로필 수정 · Button 을 쓰는 37개 파일
```

덮어쓰는 방법도 셋으로 갈렸다 — `inputClass` · `className` · `wrapperClassName`.

### 임시 조치가 생긴 사정

커밋 `9cccb171`(2026-08-05, #838 작업 중)이 비밀번호 찾기 화면만 `h-12`로 못 박았다.
그 커밋 메시지에 이렇게 적혀 있다.

> ⚠️ 공용 조각(Button·Input)은 안 건드린다 — 웹 **전체** 화면이 함께 바뀐다.
> 웹 전체의 높이 통일은 **별도 이슈로 남긴다**.

**그 「별도 이슈」가 이것(#847)이다.** 그때 `InputField`·`InputWithButton`에 더한
`wrapperClassName`도 이 일을 하려고 낸 길이다.

⚠️ 이 사정은 **이슈 #838 본문에는 없다.** 커밋에만 있다.

## 3. 정한 것 — 높이

### 웹

```
        모바일   데스크탑        지금
sm       40       36           36 고정
md       48       40           40 고정
lg       56       48           48 고정
xs       없앤다                 sm 과 값이 같았다
```

**방식은 `h-*` 고정으로 바꾼다.** 글자 크기를 바꿔도 줄이 안 흔들린다.
반응형은 **모바일이 크고 `md:`에서 작아지는** 방향이다 — 지금과 반대다.

### 앱

```
48   화면을 끝내는 단추         프로필수정 52→48 · 비밀번호찾기 44→48
46   창 안 단추                그대로
40   댓글 등록                 그대로
```

⚠️ **46·40을 억지로 맞추지 않는다.** 창 안 단추를 화면 아래 단추만큼 키우면 작은 창이
답답해지고, 댓글 등록을 48로 키우면 옆 입력칸보다 커져 줄이 안 맞는다. **자리가 다르면
크기도 다른 것**이 맞다.

## 4. 정한 것 — 색 (#786에서 넘어옴)

### 입력칸 테두리

```
웹 지금    outline-variant #d4c4b2   1.55:1  ❌
          gray-400 #a0aec0          2.05:1  ❌   로그인·가입이 쓰는 값
바꿈       #D1D5DB                   1.47:1  ❌   앱과 같은 값
```

⚠️ **WCAG 1.4.11(UI 조각 3:1)을 못 넘긴다. 알고 고르는 값이다.**
입력칸은 이름표와 안내글이 이미 「여기 쓰는 칸이다」를 말해 주므로 테두리가 유일한 단서가
아니다. 앱이 19바퀴에 같은 판단을 했고(당근마켓 입력칸에서 뽑은 값과 사실상 같다),
기준을 넘는 `#8d8d8d`(3.02:1)는 **눈에 익은 선보다 진해 보인다.**

### 주 단추

```
웹 지금    #633F00   primary-700   9.37:1
바꿈       #825500   primary-600   6.46:1   앱이 19바퀴에 정한 값
```

둘 다 기준을 넉넉히 넘는다. 두 색의 차이는 1.45:1이라 **나란히 놓으면 거의 같아 보인다** —
어느 쪽으로 모으든 화면 인상은 크게 안 바뀐다. 앱 쪽으로 모으는 이유는 19바퀴에 실기기로
보며 정한 값이라 근거가 쌓여 있어서다.

## 5. 걷어낼 임시 조치

공용 조각이 의도대로 바뀌면 화면마다 덮어쓴 것이 필요 없어진다.

```
login/LoginForm.tsx            inputClass="py-3" · py-3 md:py-2
login/SocialLoginButtons.tsx   py-3 md:py-2
find-password/FindPasswordForm.tsx   wrapperClassName="h-12" 네 곳
```

`wrapperClassName` **속성 자체는 남긴다** — 밖에서 높이를 줄 수 있는 길은 있어도 된다.
쓰던 자리만 걷어낸다.

## 6. 위험한 곳

**웹 전체가 영향받는다.** 이것이 #838에서 공용 조각을 못 건드린 이유였다.

```
Button          37개 파일
입력칸           11개 파일 (로그인·가입·비밀번호찾기·상품등록·프로필수정)
sm 36 → 40      43곳이 4px 커진다  ← 가장 넓게 퍼진다
```

`LoginForm.tsx` 주석이 경고한 그 일이다.

> `size="sm"` 자체를 고치면 홈 필터·채팅 등 **28개 파일이 같이 커진다**

⚠️ **줄이 좁은 곳이 특히 위험하다.** 홈 필터 알약·채팅 입력줄처럼 여러 개가 가로로
늘어선 자리는 4px이 커지면 줄바꿈이 생길 수 있다.

### ⚠️ 게이트는 높이가 틀린 걸 못 잡는다

타입체크도 lint도 `h-11`과 `h-12`를 구분 못 한다. **19바퀴에서 색으로 겪은 것과 같다** —
수치로 재고 눈으로 봐야 한다. 다행히 높이는 색과 달리 **개발자도구로 정확히 잴 수 있다.**
