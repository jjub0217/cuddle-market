# 앱 커뮤니티 목록을 홈과 같은 얼개로 — 설계

> 2026-08-17(월). 헤더·탭·검색·정렬 넷을 홈 화면 쪽으로 맞춘다.

## 왜 하나

앱 안에서 **같은 성격의 줄이 화면마다 다른 모양**이다. 홈과 커뮤니티는 둘 다 「위에서 갈래를 고르고, 아래 목록을 본다」인데 생김새가 갈려 있다.

```
홈        로고           [🔍][🔔][☰]      대분류 = 밑줄이 미끄러지는 탭    검색 = 헤더 돋보기 → 검색 화면
커뮤니티   「커뮤니티」        [🔔][☰]      게시판 = 알약                 검색 = 목록 위 검색칸
```

## 무엇을 기준으로 정했나 — 여기가 갈림길이었다

지금 커뮤니티 화면은 **「웹과 같게」**를 기준으로 짜였다. 코드에 그 이유가 적혀 있다.

```
post-search-input.tsx:9    웹도 커뮤니티는 목록에 검색창을 얹는다. 상품은 「찾을 게 정해져 있어
                           들어오는」 흐름이라 별도 화면이고, 커뮤니티는 보다가 찾게 되므로
                           보던 자리에 칸이 있는 게 맞다
community-sort-row.tsx:6   셋뿐이라 시트로 감추지 않고 나란히 펼쳐 둔다. 모양은 웹과 같다
```

이번에는 기준을 **「앱 안에서 같게 — 단 이득이 큰 것만」**으로 바꾼다. 웹과 갈리는 것을 알고 받아들인다.

⚠️ **그러니 앞으로 웹 커뮤니티를 고칠 때 「앱은 왜 다르지」로 헷갈리지 말 것.** 이 문서가 그 답이다.

## 정한 것 넷

### ① 헤더 — 오른쪽만 맞춘다. 왼쪽은 그대로

```
홈        [로고]          [🔍][🔔][☰]
커뮤니티   커뮤니티         [🔍][🔔][☰]     ← 돋보기만 더한다
마이       마이페이지            [🔔][☰]
```

**로고로 바꾸지 않는다.** 로고는 「홈」을 뜻하고 누르면 목록이 처음 상태로 돌아가는 단추다. 커뮤니티에 두면 **지금 어느 탭인지 알려주는 유일한 글자가 사라진다.** 마이 탭도 제목을 쓴다.

`AppHeader` 는 이미 이 모양을 받게 돼 있다 — `right` 주석에 「홈의 검색 돋보기가 여기 들어온다」라고 적혀 있다. 조각을 고칠 일이 없다.

### ② 탭 — 알약을 버리고 밑줄이 미끄러지는 탭으로

「질문 있어요 / 정보 공유」를 홈의 대분류 탭과 같은 모양으로 바꾼다. 바 하나가 옆으로 **미끄러지는** 그 탭이다.

⚠️ 지금 그 탭은 `product-filter-row.tsx` 안에 **갇혀 있다**(`PetTypeTabRow`, 내보내지 않는다). 공용 조각으로 뽑아낸다. 상품 쪽도 그 조각을 쓰게 바꾼다 — **한쪽에만 있는 조각은 같은 것을 화면마다 다르게 보이게 한다**(18바퀴에 날짜 표기에서 실제로 겪었다).

공용 조각이 알아야 하는 것은 **「고를 것들」과 「지금 고른 것」**뿐이다. 「전체」가 있고 없고는 쓰는 쪽이 정한다 — 상품은 있고 커뮤니티는 없다.

**알약(`StatusFilterChips`)은 없애지 않는다.** 마이 목록·판매자 프로필이 계속 쓴다. 거기는 **상태를 걸러내는 것**(판매중·예약중)이고 커뮤니티 게시판은 **갈래를 고르는 것**이라, 둘이 다른 모양인 편이 맞다.

### ③ 검색 — 헤더 돋보기 → 검색 화면 → **목록으로 돌아와** 검색어가 걸린다

```
【평소】                      【검색 중】
┌────────────────┐        ┌────────────────┐
│ 커뮤니티  [🔍][🔔][☰] │        │ ‹  [사료      ✕] │ ← 헤더만 검색줄로
├────────────────┤        ├────────────────┤
│ 질문있어요  정보공유 │        │ 질문있어요  정보공유 │ ← 탭 그대로
│ ━━━━━━         │        │ ━━━━━━         │
│   최신순|조회|댓글  │        │   최신순|조회|댓글  │ ← 정렬 그대로
│ 글 …               │        │ 글 …               │
├────────────────┤        ├────────────────┤
│ 홈 커뮤 플레이스 채팅 마이 │        │ 홈 커뮤 플레이스 채팅 마이 │ ← 탭바 남는다
└────────────────┘        └────────────────┘
```

**상품처럼 별도 결과 화면을 만들지 않는다.** 상품의 `/search-result` 는 탭 밖(루트)이라 **하단 탭바가 사라진다.** 커뮤니티는 「보다가 찾는」 흐름이라 탭 안에 머무는 게 맞고, 무엇보다 **검색 결과에서도 게시판 탭이 계속 보여야 한다**는 것이 이번 요구다.

- 검색 화면은 상품이 쓰는 것과 **같은 검색줄 조각**(`SearchBarHeader`)을 쓴다. 두 화면의 검색줄이 같은 모양이라 오갈 때 글자가 안 들썩인다.
- 검색어를 확인하면 커뮤니티 목록으로 **돌아오면서** 검색어를 넘긴다. 목록 화면은 그 값을 조건으로 쓴다.
- 검색 중에는 헤더가 검색줄로 바뀐다 — 지금 무엇을 찾는지 늘 보이고, 눌러서 바로 고칠 수 있다. 상품 결과 화면이 그렇게 한다.
- 검색을 풀면(✕·뒤로) 평소 헤더로 돌아온다.

**`PostSearchInput` 은 쓰는 데가 없어진다.** 그래도 **이번에는 안 지운다** — 안 쓰게 된 파일은
따로 모아 두었다가 나중에 한 번에 정리하기로 했다. 지금 지우면 이 작업의 diff 에 「기능 바꾸기」와
「파일 치우기」가 섞인다.

⚠️ 그러니 **아무도 안 쓰는 조각과 시험이 한동안 남는다.** 다음 사람이 「이건 어디서 쓰나」로
헤매지 않게, 조각 맨 위에 **「지금은 아무도 안 쓴다 · 치울 목록에 있다」**를 적어 둔다.

### ④ 정렬 — 모양은 그대로, **자리만 목록 밖으로**

셋을 나란히 펼쳐 둔 지금 모양이 낫다. 한 번에 고르고, 지금 무엇으로 정렬 중인지 늘 보인다. 시트로 접으면 누르는 횟수가 늘고 가려진다 — **셋뿐이라 접을 이유가 약하다.**

바꾸는 것은 **자리 하나**다. 지금은 목록의 헤더(`ListHeaderComponent`)라 **위로 올리면 사라지고, 목록이 비면 아예 안 보인다.** 목록 **밖 형제**로 옮긴다.

```
지금                          바꾼 뒤
[탭]        ← 목록 밖          [탭]        ← 목록 밖
[검색칸]     ← 목록 밖          [정렬 줄]    ← 목록 밖으로 옮긴다
─ 목록 ─                      ─ 목록 ─
 [정렬 줄]   ← 스크롤되어 사라짐    글들
 글들
```

⚠️ **「붙는 줄(sticky)」로 만들지 않는다.** 정렬 줄은 목록 안에서 **맨 처음**이라, 붙여 두는 것과 목록 밖에 두는 것이 **눈에는 똑같다.** 그런데 붙는 줄로 만들면 방금 #935 에서 잡은 고장(붙은 줄 안의 누름판이 안 먹는 리액트 네이티브 회귀)을 **복제하게 된다.** 같은 결과를 더 단순한 방법으로 얻는다.

## 무엇을 안 하나 (YAGNI)

```
검색 화면의 최근 검색어·추천어    안 만든다. 상품 검색 화면에도 아직 없다
커뮤니티 세부 필터(⚙)          없다. 만들 이유가 없다
정렬을 시트로                  안 한다(④)
알약 조각을 없애기              안 한다. 마이·판매자 프로필이 쓴다(②)
```

## 웹과 갈리는 곳 — 표로 남긴다

| | 웹 커뮤니티 | 앱 커뮤니티(이 설계) | 왜 |
|---|---|---|---|
| 검색 | 목록 위 검색창 | 헤더 돋보기 → 검색 화면 | 앱 안에서 상품과 같게. 세로도 번다 |
| 게시판 고르기 | 알약 | 밑줄 탭 | 앱 안에서 홈과 같게 |
| 정렬 | 나란한 줄 | 나란한 줄 (자리만 위로) | 웹과 같다 |
| 헤더 | — | 제목 + 돋보기·벨·메뉴 | 앱 안에서 홈·마이와 같게 |

## 어떻게 확인하나

**시험(jest)으로 지킬 것**

```
탭을 바꾸면 그 게시판으로 다시 부른다        (지금 시험이 이미 있다 — 안 깨지게)
검색어가 오면 그 조건으로 부른다
검색어를 풀면 조건 없이 부른다
목록이 비어도 탭·정렬 줄은 보인다            ← 정렬 줄이 목록 밖으로 나온 결과
밑줄 탭 조각: 고른 것이 바뀌면 알린다
상품 쪽이 그 조각을 써도 전과 같이 돈다      (기존 시험이 그대로 통과해야 한다)
```

**눈으로 봐야 하는 것 (jsdom 이 못 보는 것)**

```
밑줄 바가 미끄러지는가 · 고른 탭이 화면 안으로 따라오는가
검색줄로 바뀔 때 글자가 들썩이지 않는가
탭바가 그대로 남는가
```
