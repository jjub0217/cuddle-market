# 앱 세부 필터 설계 (16바퀴 · #855)

> 2026-08-06 합의. 15바퀴(#854)에서 앞줄만 넣었고 나머지를 마저 넣는다.

## 1. 무엇을 만드나

15바퀴에서 넣은 것은 **검색어 · 반려동물 대분류 · 카테고리** 셋뿐이다.
서버(`ProductSearchRequest`)가 받는 나머지를 마저 붙인다.

```
반려동물 상세 종류   최대 8개   대분류마다 다르다 (포유류 8, 나머지 4)
상품 타입           3개       전체 · 판매 · 판매요청
상품 상태           4개       새 상품 · 거의 새것 · 사용감 있음 · 수리 필요
가격               4구간      1만 이하 · 1만~5만 · 5만~10만 · 10만 이상
지역               17 → 최대 30   시/도 → 시/군/구
정렬               4개       최신순 · 저가순 · 고가순 · 찜 많은 순
```

**서버 작업은 0이다.** 앱이 이미 `/products/search` 를 부르고, 15바퀴에서 조건을 얹는 길을
내 두었다(`ProductListParams`).

## 2. 화면 모양

```
┌──────────────────────────┐
│ 대분류 알약 (9)            │  ↑
│ 소분류 알약 (골랐을 때만)    │  │ 목록과 함께 스크롤되어 사라진다
│ 카테고리 이미지 (8)         │  ↓
├──────────────────────────┤
│ [전체][판매][판매요청]  [⚙] 정렬▾ │  ← 이 줄만 고정
├──────────────────────────┤
│ 목록                      │
└──────────────────────────┘
```

**판매/판매요청이 목록 바로 위인 이유** — 웹이 그 자리다(`ProductsSection.tsx:76`).
정렬과 한 묶음이다. 「무엇을 찾을까」가 아니라 **「목록을 어떻게 볼까」**로 묶은 것이다.

**필터 줄이 스크롤되어 사라지는 이유** — 네 줄을 다 고정하면 약 224dp, 폰 내용 높이의
**3분의 1**이 필터가 된다. 올리브영도 필터 줄이 스크롤되고 결과 줄만 붙어 있다.

⚠️ 번개장터·올리브영은 **검색 결과 화면**만 이렇게 빽빽하고 홈에는 필터가 없다.
   우리는 목록 조각이 하나라 **홈에도 똑같이 생긴다** — 그래서 스크롤되게 하는 것이 더 중요하다.

⚠️ **상품 개수(「상품 768」)는 넣지 않는다.** 참고 앱에는 있지만 **웹에 없다** —
   만들어 두고(`ProductListHeader`) 주석 처리해 뒀다. 정말 필요하면 웹부터 켜는 것이 순서다.

## 3. 소분류는 「더보기」가 필요 없다

세어 보니 대분류마다 **최대 8개**다(포유류 8, 나머지 4개씩). 가로 스크롤 한 줄로 충분하다.

```
대분류가 「전체」   소분류 줄이 아예 없다
대분류를 고르면    그 아래 소분류 줄이 나타난다
```

⚠️ 대분류를 바꾸면 **고른 소분류를 푼다.** 조류를 골라 놓고 대분류를 파충류로 바꾸면
   맞지 않는 조건이 남는다.

## 4. 세부 필터는 아래에서 올라오는 시트다

```
┌──────────────────────────┐
│         ──               │  손잡이
│ 상품 상태                  │
│ [새 상품][거의 새것][사용감][수리] │
│                          │
│ 가격                      │
│ [1만 이하][1만~5만][5만~10만][10만 이상] │
│                          │
│ 지역                      │
│ [서울][부산][대구] …        │  시/도 17개
│ [강남구][강동구] …          │  고른 시/도의 시/군/구 (줄바꿈)
│                          │
│ [초기화]          [적용]    │
└──────────────────────────┘
```

**왜 시트인가**
- 앱에 **이미 있는 조각**이다(`components/ui/bottom-sheet.tsx`) — 상품 ⋮ 메뉴, 가입 거주지 선택이 쓴다
- 셋을 한눈에 보고 **한 번에 「적용」**할 수 있다
- 줄이 안 늘어난다 — `⚙` 하나만 정렬 옆에 붙는다

**지역은 시트 안에서 줄바꿈(wrap)으로 펼친다.** 시/군/구가 **최대 30개**라(경기도)
가로 한 줄로는 무리다. 시트는 세로 여유가 있다.

⚠️ 지역도 **고르면 아래가 나타나는** 같은 규칙이다(대분류→소분류와 같다). 규칙이 하나면
   배우지 않아도 안다.

**「적용」을 눌러야 반영된다.** 시트 안에서 고를 때마다 목록이 바뀌면, 가려진 목록이
계속 다시 그려져 어수선하다. 앞줄 알약은 그 자리에서 바로 반영되는 것과 다르다 —
**앞줄은 하나씩 고르고, 시트는 여러 개를 모아 고른다.**

## 5. 웹과 갈리는 곳

| | 웹 | 앱 | 왜 |
| --- | --- | --- | --- |
| 세부 필터 | 단추로 펼치는 패널 | **아래에서 올라오는 시트** | 폰의 관례. 앱에 조각이 이미 있다 |
| 지역 고르기 | 드롭다운 둘 | **알약 + 줄바꿈** | 폰에서 드롭다운은 누르기 어렵다 |
| 필터 줄 | 늘 보인다 | **스크롤되어 사라진다** | 폰은 세로가 빠듯하다 |

**같은 것**: 조건의 뜻과 이름, 값(가격 구간·상태·정렬), 하나만 고르고 다시 누르면 풀리는 방식,
판매/판매요청이 목록 바로 위라는 것.

```
지역 여러 개        웹도 하나다

```

## 7. 미리 아는 함정

```
카테고리 이미지      웹 public/images/category/*.webp 8개를 **앱으로 옮겨야** 한다.
                   앱에는 아직 없다

대분류을 바꿀 때     고른 소분류를 푼다. 안 풀면 맞지 않는 조건이 남는다

시/도를 바꿀 때      고른 시/군/구를 푼다. 같은 이유다

조건이 바뀌면       목록을 **처음부터** 받는다. queryKey 에 다 넣는다
                   (15바퀴에서 겪었다 — 안 넣으면 뒤섞인 목록이 된다)

필터 줄 스크롤       지금은 FlatList **밖**에 있다. 안으로(ListHeaderComponent) 옮기면
                   빈 화면·오류일 때 필터가 사라진다 — 그러면 조건을 되돌릴 길이 없다.
                   **빈 화면에서도 필터는 보여야 한다**

시트 안 여백        시트는 루트에 그린다. `insets.bottom` 을 자기가 더해야 한다
                   (#843에서 겪었다 — 측정되는 상자에 줘야 한다)

「적용」 안 누르고 닫기  고르던 것을 버린다. 열 때의 상태로 되돌린다
```

## 8. 완료 기준

- [ ] 대분류를 고르면 소분류 줄이 나타나고, 대분류를 바꾸면 풀린다
- [ ] 카테고리가 이미지로 보인다
- [ ] 필터 줄이 목록과 함께 스크롤되어 사라진다. **빈 화면에서는 보인다**
- [ ] 판매/판매요청·정렬 줄은 고정이다
- [ ] `⚙` 를 누르면 시트가 올라오고, 상태·가격·지역을 고를 수 있다
- [ ] 「적용」을 눌러야 목록이 바뀐다. 그냥 닫으면 버린다
- [ ] 「초기화」로 시트 안의 조건이 다 풀린다
- [ ] 조건을 바꾼 뒤 스크롤해도 목록이 안 뒤섞인다
- [ ] `pnpm gate:mobile` 초록
- [ ] 실기기 — 목록이 몇 장 보이는지, 시트가 탭바에 안 가리는지
