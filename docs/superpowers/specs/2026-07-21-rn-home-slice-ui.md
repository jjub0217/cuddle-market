## 1. 이 스펙이 쓰는 "간격 규칙"(spacing scale)

[내가 정한 임의 이름] 화면 전체에서 아래 4의 배수 값만 씁니다. 값을 여기저기 다르게 쓰지 않으려는 규칙입니다. (모바일 UX 가이드 §3.2 "일관된 spacing scale")

| 이름 | 값(dp) | 용도 |
| --- | --- | --- |
| `xs` | 4 | 아주 좁은 붙임(뱃지 내부 등) |
| `sm` | 8 | 요소 사이 기본 좁은 간격 |
| `md` | 12 | 카드 내부 패딩, 카드끼리 세로 간격 |
| `lg` | 16 | 화면 좌우 기본 패딩 |
| `xl` | 24 | 섹션 사이 큰 여백(빈 상태 등) |

> dp = 화면 밀도 보정 단위(RN 기본 단위). "픽셀 비슷한 거"로 이해하면 됩니다.

## 2. 화면 전체 구조

### 2.1 세로 구성

```
┌─────────────────────────────┐
│ ▓▓▓ 상태바 영역(시계·배터리) ▓▓▓ │ ← Safe Area 상단 inset (건드리지 않음)
├─────────────────────────────┤
│  커들마켓            (헤더)   │ ← 최소 헤더 (아래 2.3)
├─────────────────────────────┤
│                             │
│  [ 상품 카드 ]               │
│  [ 상품 카드 ]     ← 세로     │
│  [ 상품 카드 ]        스크롤   │
│  [ 상품 카드 ]      영역      │
│         ⋮                   │
│                             │
├─────────────────────────────┤
│ ▁▁▁ 홈 인디케이터 영역 ▁▁▁    │ ← Safe Area 하단 inset (콘텐츠 안 깔림)
└─────────────────────────────┘
```

- 구조: **최소 헤더 + 본문 세로 스크롤 목록**. (모바일 UX 가이드 §3.1)
- 이 슬라이스엔 **하단 5탭 없음, 상단 필터/검색/정렬 UI 없음, 상세 이동 없음** (요구사항 §2.2 OUT).

### 2.2 Safe Area 처리 (필수)

근거: 모바일 UX 가이드 §2.3, §10.

- **상단**: 헤더는 상태바(시계·노치) inset **아래**에서 시작. → `SafeAreaView` 또는 `useSafeAreaInsets().top`만큼 헤더 상단에 여백.
- **하단**: 목록 스크롤 영역의 **마지막 카드 아래에 하단 inset만큼 여백**을 둬서, 마지막 카드가 홈 인디케이터(아이폰 아래 막대)에 가려지지 않게 함. → 리스트 `contentContainerStyle`의 `paddingBottom = insets.bottom + md(12)`.
- iOS(노치·홈 인디케이터)뿐 아니라 **Android 제스처 내비게이션**에서도 동일하게 하단 inset 반영.

### 2.3 헤더 (최소 구성)

- 이 슬라이스는 상세 이동이 없으므로 **뒤로가기 버튼 없음**.
- 헤더에는 **앱/화면 이름 텍스트 "커들마켓" 하나만**. 검색 아이콘·필터·등록(+)·알림 등 **액션 아이콘은 넣지 않음**(모두 OUT).
- 상단 sticky 헤더는 화면 제목 정도만 둔다는 가이드(§3.3)와 일치.
- 높이는 플랫폼 기본 헤더 높이 수준(약 44~56dp). 좌측 정렬 제목 권장.

> 헤더를 아예 없애도 요구사항 위반은 아니나, "지금 어느 화면인지" 최소 맥락을 위해 제목만 있는 얇은 헤더를 권장합니다.

## 3. 목록 레이아웃 — **1열 리스트(가로형 카드)로 결정**

### 3.1 결정과 근거

**결정: 1열 세로 리스트 + 가로형 카드(썸네일 좌측 정사각 + 정보 우측).**

근거:

1. **웹 홈의 모바일 기본이 이미 1열 가로 카드**입니다. `ProductCard.tsx`의 `vertical` 기본값은 `false`이고, 이때 모바일(<768px)에서 `flex-row-reverse`(가로 배치)로 렌더됩니다(line 80). 2열 그리드용 세로 카드(`vertical=true`)는 마이페이지 같은 특수 화면에서만 씁니다(line 20~26 주석). → 홈의 "웹 진실"은 1열 가로 카드.
2. **국내 중고거래 앱 표준 피드 패턴**(당근마켓 계열): 한 행에 제목·가격·위치·찜·시간까지 담아 **훑어보기(스캔)** 에 유리. 요구사항 §1 "뭐가 있나 구경"이라는 이 슬라이스 목적에 맞음.
3. **얇은 슬라이스라 구현이 단순**: 세로 리스트 하나(`FlatList`)면 되고 2열 그리드 계산(`numColumns`)이 불필요. 경로 검증이 목적(요구사항 §1)이라 가장 가벼운 정답.
4. **거래상태 오버레이 pill이 작은 정사각 썸네일 중앙에도 또렷하게** 보임(§4.1).

**트레이드오프(안 고른 쪽):** 2열 그리드(썸네일 위·정보 아래)는 사진을 크게 강조하고 한 화면에 더 많이 보여줘 시각 위주 상품(반려동물 용품 사진)에 유리합니다. 다만 카드 폭이 좁아 위치·찜·시간 같은 **메타 정보를 줄여야** 하고 구현도 더 복잡합니다. → **다음 루프에서 필터·정렬과 함께 그리드 전환을 재검토**하는 게 맞고, 이 슬라이스에선 1열이 정답.

### 3.2 목록 여백·간격

- 좌우 화면 패딩: `lg(16)` 고정. (데스크톱식 넓은 양옆 여백 금지 — §3.2)
- 카드끼리 세로 간격: `md(12)`.
- 리스트 상단 첫 카드 위 여백: `md(12)`.
- 리스트 하단: `insets.bottom + md(12)` (2.2 참고).
- 카드는 좌우 패딩 안에서 **화면 폭을 꽉 채움**(§3.2 "카드형 UI는 화면 폭을 적극적으로 사용").

## 4. 상품 카드 레이아웃 (가로형)

### 4.1 카드 골격

```
┌───────────────────────────────────────────┐
│ ┌─────────┐  [판매] [거의새것]              │ ← 뱃지 행
│ │         │                                │
│ │ 썸네일   │  강아지 자동 급식기 팝니다         │ ← 제목 (최대 2줄)
│ │  1:1    │                                │
│ │ (오버레이│  35,000원                       │ ← 가격 (강조)
│ │  가능)  │                                │
│ └─────────┘  은평구 · 찜 15        3시간 전   │ ← 메타 행
└───────────────────────────────────────────┘
   좌: 썸네일        우: 정보 영역(flex 1)
```

- 카드 컨테이너: 흰 배경, 모서리 라운드(약 12dp), 아주 옅은 테두리 또는 약한 그림자 1단계. 내부 패딩 `md(12)`.
- 좌측 **썸네일**과 우측 **정보 영역**을 가로로. 둘 사이 간격 `md(12)`.
- 웹은 모바일에서 이미지를 **오른쪽**에 뒀지만(`flex-row-reverse`), 앱에서는 **국내 중고거래 관습대로 이미지를 왼쪽**에 둡니다(시선이 사진 먼저 → 오른쪽 텍스트). 웹과의 이 좌우 차이는 의도된 네이티브 번역입니다.

### 4.2 썸네일

- **비율 1:1 정사각**, 한 변 약 `96~104dp`. 모서리 라운드(약 8dp), 넘침 잘라내기(`overflow: hidden`).
- 이미지 채움: `resizeMode: cover`(꽉 채우고 넘치는 부분 잘림).
- 데이터: `mainImageUrl` (완성형 절대 URL, 그대로 사용 — 요구사항 §6.3-4). RN에서는 `Image`/`expo-image`.
- **거래상태 오버레이는 이 썸네일 위에 덮음**(§5에서 상세).
- **웹의 찜 하트 버튼(썸네일 우상단)은 이 슬라이스에서 썸네일 위에 두지 않음** — 찜은 토글이 OUT이고, "표시만" 하는 찜 개수는 정보 영역 메타 행에 둡니다(§4.3). 썸네일 위에는 거래상태 오버레이만.

### 4.3 정보 영역 (썸네일 오른쪽, 위→아래 순서)

시각 계층(위가 보조 정보, 가운데가 핵심, 아래가 메타):

1. **뱃지 행** (제일 위, 가로 나열, 간격 `xs(4)`)
   - **판매유형 뱃지**: `productType` → "판매" / "판매요청". (근거: `ProductInfo.tsx` line 28~33)
     - "판매요청"은 눈에 띄는 톤(주황 계열), "판매"는 차분한 톤(파랑/회색 계열)으로 구분.
   - **상품상태 뱃지**: `productStatus` → "새상품/거의새것" 등. 외곽선(outline)만 있는 담백한 톤.
   - 뱃지는 작은 pill(둥근 모서리), 폰트 아주 작게(약 11dp).
   - 값이 없으면 해당 뱃지는 렌더하지 않음(빈 뱃지 금지).
2. **제목** (`title`)
   - 본문보다 조금 크고 약간 굵게(약 14~15dp, medium). **최대 2줄**, 넘치면 말줄임(`…`).
3. **가격** (`price`)
   - **가장 굵고 진하게**(약 16dp, bold) — 카드에서 시선 최우선. "35,000원"처럼 천 단위 콤마 + "원".
4. **메타 행** (제일 아래, 회색 작은 글씨 약 12dp)
   - 왼쪽부터: **위치** · **찜 아이콘+개수**  …(여백)… **상대시간**(오른쪽 끝 정렬)
   - 위치: `addressGugun` 우선, 없으면 `addressSido`, 둘 다 없으면 생략(구분점도 생략). (근거: `ProductCard.tsx` line 57)
   - 찜: **`찜 15`처럼 "찜 " + `favoriteCount` 숫자 텍스트**(아이콘 아님). 근거: 웹 `ProductInfo.tsx` line 55 `label={\`찜 ${favoriteCount}\`}`. **표시 전용 — 누르는 동작 없음**(요구사항 §2.2, §4). 하트 아이콘은 쓰지 않습니다.

## 5. 거래상태 오버레이 시각 상세 (요구사항 §4.1 위임분 — 구체값 못박음)

근거: 웹 `ProductThumbnail.tsx` line 49~50, 92~98.

### 5.1 언제 씌우나 (요구사항 §4.1 재확인)

| 상태(라벨) | 오버레이 | 스크림(어둡게) | 중앙 pill |
| --- | --- | --- | --- |
| 판매중(SELLING) | **없음** | — | — |
| 요청중(판매요청+상태없음) | **없음** | — | — |
| 예약중(RESERVED) | **표시** | 옅게 | "예약중" |
| 판매완료(COMPLETED) | **표시** | 진하게 | "판매완료" |
| 요청완료(판매요청+COMPLETED) | **표시** | 진하게 | "요청완료" |

즉 **판매중/요청중은 썸네일 위에 아무것도 없음.** 예약중은 살짝 어둡게, 완료 계열은 더 어둡게 + 중앙 흰 pill.

### 5.2 스크림(어두운 막) 구체값

- 썸네일 이미지 **전체를 덮음**(`position: absolute; inset: 0`, 썸네일 라운드 안쪽으로).
- **예약중**: 검정 **불투명도 40%** → `rgba(0, 0, 0, 0.40)`. (웹 `bg-black/40` 그대로)
- **완료 계열(판매완료·요청완료)**: 검정 **불투명도 60%** → `rgba(0, 0, 0, 0.60)`. (웹 `bg-black/60` 그대로)
- 이 2단계(40% / 60%) 차이가 "예약 < 완료"의 무게감을 만듭니다.

### 5.3 중앙 pill(상태 글자) 구체값

웹 값(`rounded-full bg-white/95 px-4 py-1.5 text-xs font-bold text-gray-900 shadow-md`)을 RN 값으로 번역:

- **위치**: 스크림 위, 썸네일 **정중앙**(가로·세로 중앙 정렬).
- **모양**: 완전 둥근 알약형 → `borderRadius: 999`.
- **배경**: 흰색 95% 불투명 → `rgba(255, 255, 255, 0.95)`.
- **여백(패딩)**: 좌우 `16`(≈px-4), 상하 `6`(≈py-1.5).
  - 단, 이 슬라이스 썸네일이 96~104dp로 작으므로 pill이 넘치면 **좌우 12 / 상하 4**로 축소 허용(글자가 썸네일 폭을 넘지 않게).
- **글자**: 상태 라벨(예약중/판매완료/요청완료). 폰트 약 **11~12dp, bold(700)**, 색 **진회색 `#111827`(웹 gray-900)**.
- **그림자**: 아주 약한 그림자 1단계(pill이 스크림 위에서 떠 보이게). iOS `shadowOpacity ~0.2`, Android `elevation: 2` 수준.


## 6. 3상태 화면 (로딩 / 빈 / 오류)

기준: 요구사항 §5 + 모바일 UX 가이드 §6 + PRD §5.3. **세 상태는 서로 명확히 구분**(요구사항 §7).

### 6.1 로딩 상태 — 전체 화면 스켈레톤

- **첫 진입 로딩이므로 화면 전체 스켈레톤**(UX 가이드 §6.1, 요구사항 §5.1). "빈 화면 멍 때림" 금지.
- **카드 스켈레톤 형태**: 실제 카드와 같은 골격의 **회색 뼈대**를 여러 개(약 6~8개) 세로로.

```
┌───────────────────────────────────┐
│ ┌───────┐  ▬▬▬  ▬▬                 │ ← 뱃지 자리(짧은 회색 바)
│ │▓▓▓▓▓▓▓│  ▬▬▬▬▬▬▬▬▬▬▬             │ ← 제목 자리(긴 바)
│ │▓ 회색 ▓│  ▬▬▬▬▬▬▬▬▬              │ ← 제목 2줄째
│ │▓▓▓▓▓▓▓│  ▬▬▬▬▬                   │ ← 가격 자리
│ └───────┘  ▬▬▬  ▬▬       ▬▬▬       │ ← 메타 자리
└───────────────────────────────────┘   (같은 뼈대 반복)
```

- 썸네일 자리 = 회색 사각(1:1), 제목/가격/메타 자리 = 회색 바(높이·폭만 흉내).
- 은은한 깜빡임(shimmer)은 있으면 좋고 없어도 됨(과설계 금지). **무한 스피너만 덜렁 두는 방식은 지양**(§6.1).
- 스켈레톤도 Safe Area 안에서(2.2) 스크롤 영역 안에 배치.

### 6.2 빈 상태 (성공했으나 목록 0개)

- 성공 응답인데 `data.content`가 빈 배열일 때. **오류 아님 — 확실히 구분**(요구사항 §5.2, §7).
- **화면 중앙**에 담백하게: 작은 안내 아이콘(선택) + 문구.
  - 문구 예: **"아직 등록된 상품이 없어요."** (필터가 없는 슬라이스라 이유가 단순하므로 담백하게)
  - 필요하면 한 줄 보조: "첫 상품이 올라오면 여기에서 보여드릴게요." (선택)
- 이 슬라이스엔 등록(+) 버튼이 OUT이므로 **행동 유도 버튼(CTA)은 넣지 않음**.
- 여백: 위아래 넉넉히(`xl(24)` 이상), 화면 세로 중앙 근처.

```
┌───────────────────────────────┐
│                               │
│             🐾                 │  (아이콘: 선택)
│    아직 등록된 상품이 없어요.      │
│  첫 상품이 올라오면 보여드릴게요.   │  (보조 문구: 선택)
│                               │
└───────────────────────────────┘
```

### 6.3 오류 상태 (요청 실패) — 전체 화면 오류 + 다시 시도

- 첫 로드가 실패해 **보여줄 콘텐츠가 아예 없으므로 전체 화면 오류**(요구사항 §5.3, PRD §5.3, UX 가이드 §6.3).
- **화면 중앙**에: 안내 아이콘(선택) + 문구 + **"다시 시도" 버튼**.
  - 문구 예: **"상품을 불러오지 못했어요."** + 보조 "네트워크 상태를 확인하고 다시 시도해 주세요."
  - **"다시 시도" 버튼**을 누르면 같은 요청(`GET /products/search?page=0&size=20`)을 **재요청** → 로딩 상태로 돌아감(요구사항 §3 플로우, §5.3).
- 버튼은 화면 중앙 문구 아래(엄지로 누르기 쉬운 위치). 색은 앱 기본 강조색, 충분히 큰 터치 영역(높이 ≥ 44dp).

```
┌───────────────────────────────┐
│                               │
│             ⚠️                 │  (아이콘: 선택)
│    상품을 불러오지 못했어요.       │
│  네트워크를 확인하고 다시 시도해요.  │
│        ┌────────────┐          │
│        │  다시 시도   │          │  ← 누르면 재요청
│        └────────────┘          │
│                               │
└───────────────────────────────┘
```

### 6.4 세 상태 전환 요약

```
     요청 시작
        │
        ▼
   [로딩: 전체 스켈레톤]
        │
   ┌────┴──────────────┐
   ▼                   ▼
 성공                  실패
   │                   │
 ┌─┴──────┐            ▼
 ▼        ▼      [오류: 전체화면 + 다시시도]
목록 1+   목록 0개          │
 │        │          (다시시도 탭)
 ▼        ▼               │
[카드목록] [빈 상태]  ───────┘→ 다시 로딩
```

- **로딩 ≠ 빈 ≠ 오류**를 화면이 절대 섞지 않음. 빈 상태를 오류처럼 보이게 하거나, 오류를 무한 로딩으로 방치하지 않음.

## 7. 모바일 상호작용

- **세로 스크롤**만. 목록은 위→아래로 넘겨봄. (요구사항 §2.1, UX 가이드 §2.1)
- **카드 탭 액션 없음**: 이 슬라이스는 **상품 상세 이동이 OUT**(요구사항 §2.2)이므로 **카드를 눌러도 아무 일도 일어나지 않음**. 카드에 눌리는 느낌(터치 하이라이트)이나 이동 화살표를 넣지 않아 "누르면 뭔가 되겠지"라는 오해를 주지 않음. (탭 이동은 다음 루프)
- **찜 = 표시 전용 텍스트**: 메타 행의 `찜 15` 텍스트는 정보일 뿐, 누르는 동작 없음(요구사항 §2.2). 하트 아이콘·버튼 형태로 만들지 않음(터치 영역·강조 X).
- **무한스크롤 있음**(스코프 조정 2026-07-22): 목록을 끝까지 내리면 다음 페이지를 자동 로드(`FlatList` `onEndReached` → `fetchNextPage`). 하단 footer에 **작은 "더 불러오는 중" 스피너**, `hasNext=false`면 멈춤(끝 표시는 담백하게 또는 생략). 이미 렌더된 목록은 유지 — 추가 로드 실패가 전체화면 오류로 덮지 않음(요구사항 §5.3 불변규칙).
- **이미지 로딩 실패 대체(placeholder)**:
  - `mainImageUrl` 로드에 실패하면 **회색/기본 placeholder 이미지**로 대체(빈 깨진 이미지 아이콘 방지). 웹도 실패 시 `PLACEHOLDER_IMAGES`로 폴백함(`ProductThumbnail.tsx` line 52~56 근거).
  - RN에서는 `Image`의 로드 실패 콜백(`onError`)에서 placeholder로 교체하거나, `expo-image`의 `placeholder` 사용. 실패해도 **카드 레이아웃(제목·가격 등)은 그대로 유지** — 이미지 하나 실패가 카드 전체를 깨지 않음.
  - CDN 리사이즈(150/400/800) 최적화는 **성능용이라 이 슬라이스에선 비차단**(요구사항 §6.3-4). 원본 `mainImageUrl` 그대로 넣어도 됨.

## 8. 플랫폼 주의 (iOS / Android)

근거: UX 가이드 §2.3, §10.

- **Safe Area(공통)**: 상단 상태바/노치, 하단 홈 인디케이터/제스처 바를 콘텐츠가 침범하지 않게(2.2). `react-native-safe-area-context`의 inset 사용 권장.
- **스크롤 동작**:
  - iOS: 관성 스크롤·바운스(끝에서 살짝 튕김)는 플랫폼 기본을 존중(억지로 끄지 않음).
  - Android: 오버스크롤 글로우 등 기본 동작 존중.
- **뒤로가기**: 이 슬라이스는 홈 단일 화면이라 화면 내 뒤로가기 흐름이 없음. Android 하드웨어 back은 앱 종료(기본 동작)에 맡김 — 이 슬라이스에서 별도 처리 불필요.
- **터치 영역**: "다시 시도" 버튼 등 누르는 요소는 **최소 44×44dp** 확보(엄지 조작).
- **리스트 성능**: 목록은 `FlatList`(또는 동등물)로 그려 화면 밖 카드를 재활용(첫 페이지 20개라 부담은 작지만 패턴상 권장).

## 10. 완료 기준(디자인 관점) 매핑
