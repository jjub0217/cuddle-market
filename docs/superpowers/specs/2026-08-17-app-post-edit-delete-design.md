# 앱 커뮤니티 글 수정·삭제 설계 (#924 · 24바퀴)

> 2026-08-17(월). 앱에서 **내가 쓴 글을 고치고 지울 수** 있게 한다. 지금은 웹으로 나가야 한다.

## 왜 지금인가

23바퀴에 앱 글쓰기를 만들었다(#915). 그런데 **쓰기만 되고 고치거나 지울 수는 없다.**
잘못 올린 글을 앱에서 못 지우는 것은 특히 급하다 — 지우려면 웹 브라우저를 열어야 한다.

## 이미 확인한 것 (다시 조사하지 말 것)

### 서버는 준비돼 있다

```
PATCH  /api/community/posts/{postId}    PostUpdateRequest   title · content · imageUrls · boardType
DELETE /api/community/posts/{postId}
```

### ⚠️ 서버는 사진을 따로 안 준다 — 이 설계를 가른 사실

사진 두 장이 든 글(#39)의 실제 응답이다.

```
본문 속 사진      2장   ![](주소) 로 들어 있다
imageUrls 필드   []    비어 있다
```

`PostResponse` 에 `imageUrls` 자리는 있지만 **아무도 안 채운다.** 웹도 앱도 보낼 때
빈 배열로 보내기 때문이다(#915 에서 확인). 그래서 **수정 화면은 본문에서 사진을 뽑아내야 한다.**

### 앱에 자리가 이미 있다

```
mobile/app/(tabs)/(community)/posts/[id].tsx:59    isMine 이 이미 있다
                                          :61    「글 지우기는 아직 없다」 주석
                                          :189   「내 글에는 ⋮ 를 안 그린다」
```

지금은 **남의 글에만** ⋮ 가 뜨고 그 안에 「게시글 신고하기」 하나뿐이다.

### 웹은 어떻게 하나

```
자리     본문 위 오른쪽에 「수정」·「삭제」 글자 단추 (CommunityDetail.tsx:168·178)
수정     글쓰기 화면을 다시 쓴다. 본문을 **마크다운 그대로** 편집기에 넣는다
삭제     확인창 「게시글 삭제 / 정말로 이 게시글을 삭제하시겠습니까?」
```

웹은 마크다운 편집기라 사진이 `![](주소)` 글자로 보여도 자연스럽다. **앱은 편집기가 없다.**

## 범위

### 만든다

```
내 글에 ⋮ 메뉴        지금은 남의 글에만 뜬다. 내 글에는 「수정」·「삭제」를 넣는다
삭제                  확인창을 거친다. 되돌릴 수 없다
수정                  글쓰기 화면을 다시 쓴다
```

### 안 만든다

```
댓글 수정             지금도 없다. 이 이슈 밖이다
사진 자리 옮기기       사진을 글 중간으로 넣는 일. 앱에는 마크다운 편집기가 없다
```

## 수정할 때 사진을 어떻게 다루나 — 이 설계의 알맹이

**본문에서 사진을 꺼내 사진 칸에 올린다.** 글자는 글만 남긴다.

```
서버에서 온 content              수정 화면
──────────────────────          ─────────────────
상태 좋아요                      본문: 상태 좋아요
                                사진: [A] [B]      ← 꺼내서 칸으로
![](A주소)
![](B주소)
```

저장할 때는 다시 합친다 — 글쓰기와 **같은 `buildContent`** 를 쓴다(`lib/community-post.ts`).

### 왜 이 길인가

```
✅ 쓸 때와 수정할 때가 **같은 화면**이다 — 사진을 지우고 더할 수 있다
✅ 사진 주소가 글자로 안 보인다 — 마크다운을 모르는 사람도 다룰 수 있다
❌ 사진이 글 **중간**에 있던 글은 사진이 끝으로 밀린다
```

마지막 것은 **웹에서 글 중간에 사진을 넣어 쓴 글을 앱에서 고칠 때만** 생긴다.
앱에서 쓴 글은 사진이 원래 끝에 있어 안 걸린다. 흔치 않고, 글자가 사라지는 것도 아니라
받아들인다.

### ⚠️ 글자 수는 지금과 똑같이 센다

사진을 칸으로 꺼내도 **서버 한계는 합친 본문 1000자**다. 화면의 `n/1000자` 는 사진 몫을
더한 값이다 — 글쓰기와 같다(`remainingBodyLength`). 꺼냈다고 사진이 공짜가 되지 않는다.

## 화면

### 내 글의 ⋮ 메뉴

```
지금        남의 글에만 ⋮      「게시글 신고하기」
바꾼 뒤     내 글에도 ⋮        「게시글 수정」 · 「게시글 삭제」
           남의 글은 그대로    「게시글 신고하기」
```

⚠️ 자리는 **웹과 다르다.** 웹은 본문 위에 글자 단추 둘을 늘어놓지만, 앱은 이미 ⋮ 메뉴가
그 자리에 있다(`ProductActionSheet`). **앱 안에서 「이 글로 할 수 있는 일」이 한 곳에
모여야 한다** — 채팅방·상품 상세도 그렇게 한다.

### 삭제

```
확인창    ConfirmDialog · tone="danger"
문구      웹과 같게 — 「게시글 삭제」 / 「정말로 이 게시글을 삭제하시겠습니까?」
성공      목록으로 돌아가고 목록을 무르게 한다(#922 와 같은 처리)
실패      서버 문구를 그대로 살린다
```

### 수정

`app/community-post.tsx` 를 다시 쓴다. **글쓰기 화면에 「수정 모드」를 더하는 쪽**이다.

```
들어갈 때   /community-post?postId=39
           postId 가 있으면 수정, 없으면 새 글
채우기     서버에서 글을 받아 제목·게시판을 넣고, 본문에서 사진을 꺼내 나눠 담는다
헤더       「게시글 작성」 → 「게시글 수정」
보내기     createPost → updatePost
성공       상세로 돌아가고 상세와 목록을 둘 다 무르게 한다
```

**왜 화면을 따로 안 만드나** — 제목 길이·글자 수·사진 다루기·키보드 처리가 다 같다.
따로 만들면 그 규칙이 두 벌이 되고, 한쪽만 고치는 일이 생긴다. 웹도 한 조각이 둘 다 한다
(`CommunityPostForm`).

⚠️ **대신 화면이 하는 일이 는다.** 지금 195줄인데 채우기·모드 가르기가 붙는다. 300줄을
넘으면 「채우는 일」을 훅으로 빼는 것을 생각한다.

## 새로 만드는 것

```
lib/community-post.ts 에 더한다
  splitContent(content: string): { body: string; imageUrls: string[] }
      본문에서 ![](주소) 를 뽑아 나눈다. buildContent 의 반대다
      ⚠️ 사진이 중간에 있어도 다 뽑는다. 남는 글자의 앞뒤 빈 줄은 정리한다
  updatePost(postId, input): Promise<void>       PATCH
  deletePost(postId): Promise<void>              DELETE
```

`splitContent` 는 순수 함수라 시험이 쉽다. **여기가 가장 틀리기 쉬운 자리**이므로
시험을 촘촘히 쓴다.

## 시험

```
splitContent   사진이 없는 글 · 끝에 있는 글 · 중간에 있는 글 · 사진만 있는 글
               buildContent 로 도로 합치면 사진 차례가 유지되는가
               ⚠️ 「중간에 있던 사진이 끝으로 밀린다」를 시험으로 못 박는다 —
                  의도한 대가라는 것을 다음 사람이 알아야 한다
화면           수정 모드면 제목에 원래 글이 들어 있다
               수정 모드면 헤더가 「게시글 수정」이다
               저장하면 updatePost 를 부른다(createPost 가 아니라)
메뉴           내 글이면 수정·삭제가 보인다 · 남의 글이면 신고만 보인다
삭제           확인창을 거친다 · 확인하면 deletePost 를 부른다
```

⚠️ **시험이 못 덮는 것** — 진짜 삭제·수정이 서버에 반영되는지, 사진이 실제로 다시 올라가는지.
**실기기로 봐야 한다.**
