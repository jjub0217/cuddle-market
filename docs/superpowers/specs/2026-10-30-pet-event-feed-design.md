# 반려동물 행사 소식을 모아 커뮤니티에 올린다: 설계

> 2026-10-30(금). 공공기관 사이트 4곳을 크롤링하고 관광공사 축제 API로 보완해, 커뮤니티에 "행사 소식" 게시판을 새로 연다.
> 범위는 **서버(cmarket_api) + 크롤러 + 웹**이다. 앱은 이번에 하지 않는다.

## 1. 왜 만드나

- **사용자 쪽 이유**: 반려인이 가까운 반려동물 축제, 입양 행사, 펫티켓 교육을 커뮤니티에서 한눈에 본다. 지금 커뮤니티에는 사람이 쓴 질문과 정보 글뿐이다.
- **만드는 사람 쪽 이유**: 지원하려는 회사(퍼플페퍼, AI 풀스택) 주요 업무에 "크롤링, 데이터 처리, 업무 자동화"가 있다. API를 부르는 것만으로는 크롤링 경험이 되지 않는다. 그래서 **API가 없는 공공기관 게시판을, 구조가 서로 다른 여러 곳에서** 읽는 수집 흐름을 만든다.
- 행사는 1년에 수십 건뿐이다. 건수가 아니라 **여러 사이트의 서로 다른 구조, 새 글만 가져오기, 중복 막기, 구조 변경 감지, 제각각인 날짜 정리**를 실제로 다루는 것이 목적이다.

## 2. 목표, 하지 않는 것, 실패로 보는 것

**목표**
- 하루 한 번 자동으로 수집해서, **행사인 글만** "행사 소식" 게시판에 올린다.
- 모든 행사 글은 같은 틀(4절)로 보인다.
- 출처를 하나 더하는 일이 **설정 추가 수준**이다. 같은 게시판 프로그램을 쓰는 구는 설정만 복사해 늘린다.
- 수집이 깨지면(0건, 접속 오류, 구조 변경) 디스코드로 알린다.

**이번에 하지 않는 것**
- 앱(React Native) 화면. 웹에만 연다.
- 지도(플레이스)에 행사 위치 찍기.
- 포스터 이미지를 우리 저장소에 복사하기(핫링크로만 보여 준다), 원문 본문 옮기기.
- 서울 25개 구 전부, 경기 시군.
- 반려동물 카페(네이버 카페) Q&A 수집. robots.txt가 전체 금지이고 회원 글의 저작권 문제가 있어 하지 않기로 했다.

**실패로 보는 것 (동작해도 실패)**
- robots.txt가 막은 경로를 읽는다.
- 원문 본문 문장을 싣거나 포스터를 우리 저장소에 복사한다(서울시, 노원구 글은 공공누리 4유형: 출처 표시, 상업 이용 금지, 변경 금지).
- 행사가 아닌 글(예: "반려견 순찰대 출범", "광견병 예방접종 지원")이 행사 소식에 올라간다.
- 같은 행사가 두 번 올라간다.
- AI가 지어낸 날짜, 장소, 참가비가 실린다. 본문에 없는 값은 비워 두고 "공식 안내 확인"으로 쓴다.
- 일반 사용자가 행사 소식 게시판에 글을 쓸 수 있어서, 수집 글과 사람 글이 섞인다.

## 4. 행사 글의 틀

```
제목: (수집한 행사명, 50자 이내)

![포스터](포스터 원래 주소)   (포스터가 있을 때만. 9절)

한 줄 소개: (AI, 40자 이내)

기간 | 2026.10.31 (토)
운영시간 | 오전 11시~오후 7시   (없으면 "공식 안내 확인". 2026-10-30 더함)
장소 | 서울 문화비축기지     (지역 + 구체적인 장소. 7-2절)
대상 | 반려견, 반려묘
참가비 | 무료            (없으면 "공식 안내 확인")
신청 | 사전 신청 필요(QR), 현장 접수 가능   (없으면 "공식 안내 확인". 2026-10-30 더함)
주최 | 서울특별시        (순서는 반려인이 판단하는 순서: 기간 → 장소 → 대상 → 참가비 → 주최. 2026-10-30 사용자 결정)

이런 걸 할 수 있어요
- (AI, 2~3줄)

가기 전에 확인하세요
- (AI, 1~2줄)

이 글은 주최 기관이 공개한 자료를 바탕으로 정리한 안내입니다.
일정과 참가 조건은 바뀔 수 있으니 공식 안내에서 다시 확인해주세요.
[원문 보기](원문 주소)      (누르면 원문으로 간다)
출처: (출처 이름)
```

- 틀은 **코드에 고정**한다. AI는 칸에 들어갈 값만 정해진 형식(JSON)으로 돌려준다.
- AI가 실패하거나 형식이 틀리면, AI 칸을 빼고 수집한 칸 정보만으로 같은 틀을 채운다. 글 모양은 늘 같다.
- Cuddle 글 본문은 최대 1,000자, 제목은 최대 50자다(`Post.java`). 넘으면 AI 칸부터 줄인다.

    8. 실행 결과를 정리해, 문제가 있으면 디스코드로 알린다

## 6. 출처별 차이 (2026-10-30 확인)

모두 robots.txt에서 해당 경로가 허용되고, 서버가 완성된 HTML을 보낸다.

| 출처 | 목록 주소 (검색 포함) | 상세 링크 모양 | 날짜, 장소가 있는 곳 |
|---|---|---|---|
| 문체부 지역축제 | `https://www.mcst.go.kr/site/s_culture/festival/festivalList.jsp?pSearchType=01&pSearchWord=반려` | `festivalView.jsp?pSeq={번호}` | 목록과 상세에 "기간 :", "장소 :" 칸 |
| 서울시 보도자료 | `https://www.seoul.go.kr/news/news_report.do?bbsNo=158&srchText=반려&cntPerPage=30` | `href="javascript:fnTbbsView('468820')"`에서 번호를 뽑아 `?bbsNo=158&nttNo={번호}`로 만든다 | 본문 문장 |
| 강남구 보도자료 | `https://www.gangnam.go.kr/board/B_000031/list.do?mid=ID01_0313&keyfield=bdm_main_title&keyword=반려` | `/board/B_000031/{번호}/view.do?mid=ID01_0313` | 본문 문장 (공지 B_000001은 포스터 이미지뿐인 글이 있다) |
| 노원구 보도자료 | `https://www.nowon.kr/www/user/bbs/BD_selectBbsList.do?q_bbsCode=1027&q_searchKeyTy=sj___1002&q_searchVal=반려` | `BD_selectBbs.do?q_bbsCode=1027&q_bbscttSn={번호}` | 본문 문장. 공지는 `q_bbsCode=1001` |

- **쇼알라(showala.com, 한국전시산업진흥회 운영)** — 기업이 여는 반려동물 박람회를 채운다(2026-10-30 사용자 결정, 별도 조사 뒤). robots.txt 는 `/adm/`, `/member/` 만 막는다. 「취미|기호|반려동물」 분류에 2026년 103건.
  - 목록: **첫 화면** 메뉴 「취미|기호|반려동물」 아래의 상세 링크(앞으로 열릴 행사 약 14건). 분류 목록 페이지는 처음 5건만 HTML 에 있고 나머지는 사이트가 확인하는 값(Referer, XMLHttpRequest)을 흉내 내야 받을 수 있어 **쓰지 않는다.** 하루 요청은 1 + 새 상세 수.
  - 상세: `ex_detail.php?idx={번호}`. 「전시기간」「개최장소」「세부장소」「주최」「입장료안내」「관람시간」 칸을 칸 값으로 먼저 쓰고(7-2절), 「상세정보」 글자를 AI 에 넣는다. 「문의처」(연락처·이메일)는 읽지 않는다. 포스터는 배경 그림 주소를 원래 주소 그대로 쓴다.
  - 등록일이 없어 90일 규칙 대신 끝난 행사 규칙만 쓴다. 지역은 개최장소의 전시장 이름으로 정한다(킨텍스·일산→경기, 코엑스·SETEC·aT센터→서울, 벡스코→부산, 수원메쎄·수원컨벤션센터→경기, 엑스코→대구, DCC·대전컨벤션센터→대전 등).
  - 파충류, 관상어 박람회도 넣는다. 커들마켓의 반려동물 분류(파충류, 수생동물, 양서류 등)에 들어 있다.
- 노원구는 요청 도구의 기본 접속 이름(`python-requests/…`)이면 400을 돌려준다. 모든 요청에 `CuddleEventBot/0.1 (+https://cuddle-market.vercel.app)` 형식의 접속 이름을 쓴다.
- 노원구, 고양시, 파주시는 같은 계열의 게시판 프로그램이다. 노원구 파서를 "q_ 계열" 공통 파서로 만들면, 다른 구는 설정만 더해 늘릴 수 있다. 고양시 일반 게시판은 robots.txt가 막으니 이번에 넣지 않는다.
- 공지 본문이 이미지뿐이라 글자가 거의 없으면(예: 본문 50자 미만) AI에 보내지 않고 건너뛴다. (2026-10-30 실제 실행 뒤 다시 정함) 포스터를 AI 로 읽게 하는 것은 이번에 하지 않는다. 지어낸 값을 막는 검사가 본문 글자에 기대고, 같은 행사의 보도자료(글자)가 대부분 따로 있어 둘 다 올리면 중복될 수 있다(예: 강남구 순회놀이터 공지 1076655 와 보도자료 1075431).
- 관광공사 `searchFestival2`는 서비스 키가 필요하다. 목록에는 본문이 없어서, 축제마다 소개 글(`detailCommon2`의 `overview`)을 한 번 더 받아 다른 출처의 본문처럼 AI 에 넣는다(2026-10-30 사용자 결정). 기간, 장소, 지역은 API 칸 값이 AI 값보다 먼저다. 소개 글을 못 받으면 지금처럼 AI 칸 없이 올리고 문제로 알린다. 문체부 글과 같은 행사가 겹칠 수 있어, 제목과 시작일이 같으면 하나만 올린다.

## 7. 서버 (cmarket_api)

- **게시판 종류**: `BoardType`에 `EVENT`를 더한다. 웹 탭 이름은 "행사 소식".
- **일반 글쓰기에서 막기**: 기존 글쓰기와 글 수정 API는 `EVENT`를 받으면 거절한다. 행사 소식은 수집 주소로만 들어온다.
- **수집 기록 저장**: 새 테이블 하나. 출처 코드, 출처 글 번호, 상태(게시함, 건너뜀), 만든 글 번호, 원문 주소, 수집 시각. (출처 코드, 출처 글 번호)는 겹치지 않게 한다.
- **전용 키**: 두 수집 주소는 로그인 토큰이 아니라 요청 머리글의 전용 키로 연다. 키는 서버 실행 환경 변수와 GitHub Secrets에 같은 값으로 둔다. 관리자 계정 비밀번호를 GitHub에 두지 않으려는 선택이다.
- **글쓴이**: 운영 계정 "커들소식"(회원 번호 52, `devel.jjub+cuddlenews@gmail.com`, 2026-10-30 가입). 이 번호를 서버 환경 변수로 둔다. 비밀번호는 저장하지 않았다. 로그인이 필요하면 "비밀번호 찾기"로 새로 정한다.
- 이 저장소의 엔티티는 **생성자에 `@Builder`**를 단다. 필드를 더하면 생성자도 고친다(`cuddle-market/CLAUDE.md`).
- 백엔드 컴파일과 시험은 이 맥에서 `JAVA_HOME=/opt/homebrew/opt/openjdk@21`로 돌린다(2026-10-30 설치, 전체 컴파일 통과 확인).
- 배포는 사용자가 EC2에서 한다. 새 환경 변수 2개(전용 키, 운영 계정 번호)를 실행 명령에 더해야 한다.
- **배포 전에 DB 칸 하나를 고친다** (2026-10-30 로컬에서 재현). 운영 `posts.board_type` 칸은 하이버네이트가 `enum('QUESTION','INFO')`로 만들어 두었을 가능성이 높다. `ddl-auto=update`는 이미 있는 칸을 고치지 않아서, 그대로 두면 행사 글 저장이 `Data truncated for column 'board_type'`로 실패한다. 배포 순서는 **DB 백업 → `SHOW COLUMNS FROM posts LIKE 'board_type'` → enum이면 `scripts/alter-board-type-column.sql` 실행 → 새 서버 실행**이다(cmarket_api 저장소). 예전 `pet_type` 칸도 같은 일을 겪었다(`scripts/alter-pet-type-columns.sql`).

## 7-1. 정해 둔 세부 규칙 (검토 뒤 Claude가 정함, 사용자 확인 대상)

- **끝난 행사와 첫 실행**: 끝나는 날(없으면 시작일)이 오늘보다 앞이면 올리지 않고 "건너뜀(종료)"으로 기록한다. 날짜를 하나도 뽑지 못한 글도 "건너뜀(날짜 없음)"으로 기록한다. 크롤링 출처는 목록에서 **등록일이 최근 90일 안인 글만** 상세를 읽는다. 첫 실행 때 몇 년 치 옛 보도자료가 한꺼번에 올라가지 않게 하려는 규칙이다.
- **이미 올린 행사가 끝난 뒤**: 글은 지우지 않고 그대로 둔다. 끝난 행사 표시나 숨기기는 이번 범위가 아니다.
- **출처가 달라도 같은 행사**: 수집 기록에 행사명과 시작일도 저장한다. 서버가 글을 만들기 전에 "시작일이 같고, 띄어쓰기, 연도, 기호를 뺀 행사명이 같은 기록"이 있으면 "건너뜀(중복)"으로 둔다. 같은 기관의 사전 안내와 모집 마감 안내처럼 같은 행사를 두 번 다룬 글도 이 규칙으로 걸린다. 행사명이 크게 다르게 쓰인 중복은 이번에 다 막지 못한다. 드물게 생길 수 있음을 받아들인다.
  - (2026-10-30 넓힘) 실제 실행에서 쇼알라에 「2026 크리쳐 케어로그 파충류 페스티발 - 대전」과 「크리처 케어로그 파충류 페스티벌」이 따로 올라 있어 두 번 올라갔다. 시작일이 같고 **지역도 같은**(둘 중 하나가 비어 있으면 지역은 보지 않는다) 게시 기록과 행사명 열쇠가 **비슷하면**(한쪽이 다른 쪽에 들어 있거나, 같은 글자 비율 2×공통부분/전체 길이가 0.8 이상) 중복으로 본다. 지역을 보는 까닭: 같은 날 「파충류 동반자 in 부산」과 「… in 청주」 같은 다른 행사가 합쳐지지 않게.
- **댓글과 신고** (2026-10-30 사용자 결정으로 바꿈): 행사 소식 상세에는 **댓글 영역과 신고하기 단추를 두지 않는다.** 서버도 행사 소식 글에 다는 댓글을 거절한다(화면에서만 숨기면 주소를 직접 불러 달 수 있다). 신고는 사람이 쓴 글의 욕설, 광고, 사기를 거르는 기능이라 사유가 맞지 않고, 행사 글의 문제는 「정보가 틀렸다」이므로 「공식 안내 보기」로 원문을 확인하게 하고 운영 계정이 고친다.
- **고치기와 지우기**: 일반 글쓰기에서 `EVENT`로 새 글을 만들거나, 다른 글을 `EVENT`로 옮기는 것만 막는다. 운영 계정은 웹에서 자기 글(행사 소식)을 기존 기능으로 고치고 지울 수 있다. 지운 글의 수집 기록은 "게시함"으로 남아, 다시 수집되지 않는다.
- **게시판을 고르지 않은 목록**: `GET /api/community/posts`에서 `boardType`을 비우면 지금은 모든 종류가 나온다(`PostRepositoryCustomImpl.java` 51행). 일반 조회에서는 `EVENT`를 기본으로 빼고, `boardType=EVENT`를 줄 때만 나오게 한다. 관리자 목록은 모두 보인다. 앱이 `EVENT` 글을 받지 않는다는 것은 만들면서 확인한다.

**상세** (2026-10-30 사용자 결정: 픽케어 상세의 **배치와 정보 정리 방식만** 참고. 색, 글꼴 등 겉모양은 커들마켓 것)

- 본문 글자(마크다운)는 상세에서 그리지 않고 행사 칸으로 그린다. 본문은 행사 칸을 모르는 화면(앱, 검색)을 위해 틀 모양 그대로 저장해 둔다. 행사 칸이 없는 글(옛 글)은 본문을 그대로 그린다.
- 포스터가 없으면 포스터 자리 없이 오른쪽 내용이 넓어진다. **포스터를 못 불러와도 같은 모양으로 자리를 비운다**(2026-10-30 바꿈. 기본 그림은 중고거래용 방 그림이라 행사와 상관이 없어 오해를 부른다).
- 표의 장소는 「지역 + 장소」(예: 서울 문화비축기지). 값이 없으면 「공식 안내 확인」.
- **운영시간**(2026-10-30 더함, 픽케어 세 페이지 비교 뒤 결정): 기간 바로 아래. AI 가 본문에서 뽑고, 본문에 시각 숫자(「10시」, 「10:00」)가 없으면 버린다.
- **반려동물 행사만**(2026-10-30 사용자 결정): 「반려」로 검색하면 「반려식물」도 걸린다. 반려동물과 함께 가거나 반려동물(반려인)을 위한 행사일 때만 행사로 본다. 반려동물에는 개·고양이뿐 아니라 파충류, 관상어, 조류, 소동물 등 커들마켓 분류의 동물이 모두 들어간다(2026-10-30 더함). 반려식물, 도시농업, 정원 박람회는 행사가 아니다. AI 지시문에 넣고, 제목에 「반려식물」이 있으면 AI 에 보내기 전에 「행사 아님」으로 기록한다.
- **운영시간은 적힌 그대로만**(2026-10-30 실제 실행에서 AI 가 「오후 12시 토크」「18:00~20:00 영화」를 이어 붙여 「오전 12시~오후 8시」를 만들었다): 운영시간 속 숫자가 하나라도 본문에 그대로 없으면 버린다. AI 지시문에 「프로그램별 시간을 합쳐 만들지 말고, 전체 운영시간이 없으면 null」을 넣는다.
- **AI 실패는 까닭을 남기고 한도 오류면 기다렸다 다시 한다**(2026-10-30 실제 실행에서 강남구 4건이 「AI 추출 실패」로만 남았다): 오류 종류와 메시지를 문제 목록에 남긴다. 요청 한도(429)나 일시 오류(500, 503)는 기다렸다가 두 번까지 다시 한다. 무료 등급 한도를 넘지 않게 AI 요청 사이를 4초 이상 둔다.
- **출처에 칸으로 적힌 값이 먼저다**(2026-10-30 더함): 문체부 상세는 「개최기간(| 시간)」「축제장소」「요금」「주최/주관기관」「연령제한」을 칸으로 따로 적는다. 크롤러는 이 값을 AI 값보다 먼저 쓴다(기간, 운영시간, 장소, 참가비, 주최, 대상). AI 는 한 줄 소개와 목록만 맡는다. AI 가 틀린 날을 고르는 일을 막는다.
- **신청**(2026-10-30 더함, 픽케어 박람회 상세의 「사전등록」을 보고 결정): 참가비 아래. 「가서 그냥 들어가면 되나?」에 답한다(사전 신청 필요·마감일·현장 접수). AI 가 본문에서 뽑고, 본문에 「신청·접수·예약·등록」이 하나도 없으면 버린다. 마감일 같은 날짜가 있으면 그 월·일이 본문에 있어야 한다.
- **칸 값에도 최소한의 검사**(2026-10-30 더함): 출처가 칸에 잘못 적는 일이 있다(쇼알라 크리쳐 케어로그 대전의 「관람시간」 칸에 주소가 적혀 있었다). 운영시간 칸 값에 시각 숫자(10:00, 10시)가 없으면 그 칸 값은 쓰지 않는다. 기간 칸 값에서 날짜를 못 읽으면 그 칸 값도 쓰지 않는다.
- **관광공사 소개 정보 칸(`detailIntro2`)**(2026-10-30 더함): 축제(콘텐츠 종류 15)의 운영시간(`playtime`), 이용요금(`usetimefestival`), 주최(`sponsor1`), 연령 제한(`agelimit`), 예매처(`bookingplace`), 행사 장소(`eventplace`)를 칸 값으로 먼저 쓴다. 실제 칸 이름은 로컬 실행으로 확인한다.
- 문의 전화 칸은 두지 않는다(2026-10-30 사용자 결정. 기관 대표 번호가 아닌 개인 담당자 번호가 섞여 올 수 있다).
- **길찾기**(2026-10-30 더함): 장소 칸 오른쪽의 작은 링크. 누르면 네이버 지도에서 「지역 장소」를 검색한 화면이 새 창으로 열린다(`https://map.naver.com/p/search/{검색어}`). 검색어에서는 「일원」「일대」「주변」「인근」, 괄호, 「및 …」 뒤를 뺀다(예: 「한라체육관 일원」→「한라체육관」, 「문화광장 및 T2」→「문화광장」). 관광공사 글은 장소가 주소라 그대로 검색된다. 장소가 여러 곳(쉼표)이면 첫 번째 장소로 찾는다(2026-10-30 사용자 결정. 표에는 모두 보인다). 우리 지도(플레이스)에 찍는 것이 아니라 바깥 지도로 보내는 링크다. 장소가 없거나 「온라인」이면 보이지 않는다.
- 스크랩, 공유, 캘린더 담기는 이번 범위가 아니다. 원문 문장을 옮기는 「상세 안내」도 두지 않는다(공공누리 조건).

**지역과 장소** — 목록에는 넓은 지역만, 상세에는 지역과 구체적인 장소를 같이 보인다.

| 예 | 목록 「지역 · 주최」 | 상세 본문 「장소」 줄 |
|---|---|---|
| 문화비축기지에서 열리는 서울시 행사 | 서울 · 서울특별시 | 장소 \| 서울 문화비축기지 |
| 노원구가 노원 공원에서 여는 산책 행사 | 서울 · 노원구 | 장소 \| 서울 노원 공원 |

- 지역은 시·도를 짧게 쓴다: 서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주.
- 지역을 정하는 순서: 관광공사 주소(`addr1`)의 첫 낱말 → 문체부 "장소 :" 칸의 첫 낱말 → AI가 본문에서 뽑은 값 → 출처 설정의 기본 지역(서울시, 강남구, 노원구는 서울). 어느 것도 없으면 비워 두고, 목록에는 주최만 보인다.
- 주최는 수집한 그대로 쓴다(서울특별시, 노원구 등). 없으면 출처 이름(예: 노원구)을 쓴다.

**상태 칩** — 서버에 저장하지 않고, 화면을 여는 날(한국 날짜) 기준으로 계산한다.

| 조건 | 칩 | 모양 |
|---|---|---|
| 오늘 < 시작일 | `D-n` (내일이면 D-1) | 테두리만 있는 칩 |
| 시작일 ≤ 오늘 ≤ 종료일(없으면 시작일) | `진행 중` | 색이 채워진 칩 |
| 종료일 < 오늘 | `종료` | 회색 칩, 카드 글자도 흐리게 |

- **정렬은 「최신 등록순 | 곧 끝나는 순」**(「최신순」은 행사 날짜가 최근인 순으로도 읽혀 2026-10-30 이름을 바꿈. 질문·정보 게시판은 「최신순」 그대로)(2026-10-30 사용자 결정. 조회순·댓글순은 뺀다 — 행사 글은 사람이 쓴 글이 아니라 조회수가 행사의 좋고 나쁨을 말하지 않는다). 「곧 끝나는 순」(`sortBy=ending`)은 끝나는 날(없으면 시작일, 한국 날짜 기준)이 지나지 않은 행사를 끝나는 날이 가까운 순으로 먼저, 이미 끝난 행사를 맨 아래에 둔다. 「마감 임박순」은 신청 칸의 「신청 마감」과 헷갈려 쓰지 않는다. 서버가 수집 기록의 기간으로 데이터베이스에서 정렬한다(페이지 나눔·검색·상태 거르기와 함께 맞는다).

**상태로 걸러 보기** (2026-10-30 사용자 결정으로 더함)

- 행사 소식 탭의 정렬 줄 **오른쪽**에 「드롭다운(기존 `SelectDropdown`, 홈 화면 상세 필터의 지역 드롭다운과 같은 흰 바탕·테두리 모양) · 정렬 단추」 순서로 붙여 둔다(2026-10-30 사용자 결정, 휴대폰 폭도 같다). 선택지는 전체 / 예정 / 진행 중 / 종료, 처음은 전체.
- 고른 값은 주소에 남긴다(`?eventStatus=upcoming|ongoing|ended`). 정렬, 검색어와 같은 방식이다.
- 고른 상태에 맞는 행사가 없으면 "예정된 행사가 없어요 / 지금 진행 중인 행사가 없어요 / 종료된 행사가 없어요"와 "다른 상태를 골라 보세요"를 보인다(전체일 때는 위 빈 화면 문구 그대로).
- **서버가 거른다.** 목록은 10개씩 끊어 받으므로 화면에서 거르면 페이지 수와 무한 스크롤이 어긋나고 빈 페이지가 생긴다. 커뮤니티 목록 주소가 `eventStatus`(UPCOMING, ONGOING, ENDED)를 받고, 서버가 한국 날짜의 오늘과 수집 기록의 시작일, 종료일을 위 상태 칩 표와 같은 규칙으로 비교해 거른 뒤 페이지를 나눈다. `boardType=EVENT`일 때만 쓴다.

**행사 칸 저장** — 목록에 기간, 지역, 주최, 한 줄 소개를 따로 보여 주려면 본문 글자에서 꺼낼 수 없다(목록 응답의 미리보기는 100자에서 잘린다). 그래서 크롤러가 글과 함께 이 칸들을 따로 보내고, 서버가 수집 기록에 저장해 커뮤니티 목록과 상세 응답에 행사 글일 때만 `event` 묶음으로 붙인다.

```
event: { startDate, endDate, region, place, organizer, summary,
         시작일     종료일   지역     장소    주최       한 줄 소개
         target, fee, activities, checks, sourceUrl, imageUrl, hours, application }
         대상    참가비 할 수 있는 것 확인할 것 원문 주소  포스터 주소   (상세 표와 목록용, 2026-10-30 더함)
```

## 8. 확인 방법

| 대상 | 방법 |
|---|---|
| 크롤러 파서 | 저장해 둔 실제 HTML로 출처별 시험(목록에서 번호, 제목, 상세 주소가 나오는지) |
| 날짜 정리 | "2026. 11. 6.~11. 8.", "10월 31일(토)", "2026-10-31" 같은 형식을 같은 형식으로 바꾸는 시험 |
| 틀 | AI 값이 있을 때와 없을 때 모두 1,000자 안에서 같은 모양이 나오는지 |
| 서버 | 전용 키가 없거나 틀리면 거절, 같은 (출처, 번호)는 두 번 만들지 않음, 일반 글쓰기의 `EVENT` 거절. 이 맥에서 Java 21로 시험을 돌린다 |
| 웹 | 탭, 헤더, 메타 설명. 기존 검사(타입, 린트, 시험, 빌드) 통과 |
| 끝까지 | 운영 서버에 한 번 손으로 실행해서, 행사 소식 탭에 글이 틀대로 보이는지 화면으로 확인 |

## 9. 남은 결정

없음. Java 21 설치와 운영 계정 가입은 2026-10-30에 끝냈다(7절).

**포스터 이미지** (2026-10-30 사용자 결정: 핫링크로 이번에 넣는다)
- **복사하지 않는다.** 이미지를 우리 S3에 저장하지 않고, 기관 서버의 원래 주소를 그대로 불러와 보여 준다(핫링크). 공공누리 4유형(변경 금지, 상업 이용 금지)과 2유형(상업 이용 금지) 조건을 피하려는 선택이다. 픽케어도 대부분 이 방식이다(2026-10-30 페이지 데이터에서 포스터 주소 도메인을 세어 확인).
- **어디서 가져오나**: 관광공사 API의 대표 이미지, 문체부 상세의 포스터, 구청 글에 첨부된 포스터나 본문 이미지가 있을 때만. 없으면 이미지 없이 올린다. 출처당 1장.
- **저장** (2026-10-30 사용자 결정으로 바꿈): **본문 맨 위에 사진 표시 `![포스터](원래 주소)`로 넣고**, 글의 이미지 목록(`Post.imageUrls`)에도 같은 주소를 넣는다.
  - 왜 바꿨나: 웹은 글 이미지를 **본문 안의 사진 표시에서만** 읽는다. 목록의 작은 사진은 서버가 본문에서 첫 사진 표시를 뽑아 주고(`PostListItemResponse.extractThumbnailImageUrl`), 상세는 본문을 마크다운으로 그린다(`MdPreview`). 이미지 목록은 화면에 쓰이지 않고 링크 미리보기용 대표 이미지로만 쓰인다. 로컬에서 이미지 목록에만 넣어 보니 목록 사진 칸이 비었다.
  - 대가: 본문 1,000자 안에서 주소 길이만큼 자리를 쓴다. 넘치면 AI 칸부터 줄이는 규칙은 같다.
  - 서버가 외부 주소를 받아 주는 것은 로컬에서 확인했다(2026-10-30).
- **화면**: 웹은 글 이미지 주소를 우리 저장소 규칙(`uuid_150.webp` 등)으로 바꿔 보여 준다(`src/lib/utils/imageUrl.ts`의 `toResizedWebpUrl`, `getImageSrcSet`). **우리 이미지 서버(CloudFront) 주소가 아니면 바꾸지 않고 그대로 쓰게** 고친다. 이미지를 불러오지 못하면 기존 기본 이미지로 바꿔 보여 준다.
- **한계**: 기관이 주소를 바꾸거나 다른 사이트에서 불러오는 것을 막으면 깨진다(그때는 기본 이미지). 본문이 포스터 한 장뿐인 공지는 글자가 없어 여전히 건너뛴다.
