# 12바퀴 설계 — 앱 소셜 로그인

- 이슈: #828
- 날짜: 2026-08-03 (월)
- 앞 바퀴: 11바퀴 앱 상품 등록·수정·삭제 (#826 · PR #827 머지 완료)

## 0. 한 줄 요약

앱에 **카카오·구글 간편 로그인**을 붙인다. 웹이 쓰는 서버 흐름을 그대로 쓰되, 끝나고 **돌아올 곳만 앱으로** 가른다.

## 1. 왜 이번 바퀴인가

7바퀴에 이메일 가입을 만들었지만 **칸이 아홉 개**다. 처음 들어온 사람에게는 문턱이 높다.

출시를 막는 진짜 병목은 기능이 아니라 **테스터 12명**인데(지금 3명), 앱을 깔아 본 사람이 가입에서 떨어지면 그 숫자가 안 는다. 소셜 로그인은 기능을 늘리는 게 아니라 **이미 만든 것에 사람이 닿게** 하는 일이다.

## 2. 정한 것 다섯 (2026-08-03)

```
① 제공자        카카오 + 구글        웹 로그인 화면과 같은 둘
② 서버 수정      한다 (배포까지)
③ 테스트        개발 빌드(dev client)를 한 번 만든다
                커스텀 스킴은 Expo Go에서 안 돌기 때문이다
④ 로그인 방식    1.0은 브라우저 · **1.1에서 카카오·구글 둘 다 네이티브 SDK로 바꾼다**
⑤ 추가 정보      웹과 같게 **필수로** 받는다 (닉네임·생년월일·거주지)
```

**④를 왜 브라우저로 시작하나**: 네이티브 SDK는 카카오톡 앱이 열려 비밀번호 없이 통과하는 매끄러운 경험을 주지만, 제공자마다 다른 길을 만들어야 하고 SHA-1 지문·콘솔 등록 같은 조용히 실패하는 설정이 붙는다. 1.0은 **한 방식으로 둘을 덮는 쪽**을 고른다.

**브라우저 방식의 약점을 감춰 두지 않는다**: 브라우저에 카카오 세션이 없는 사람은 **아이디·비밀번호를 쳐야 한다.** 「간편 로그인」의 값이 바로 그 비밀번호를 안 치는 것이라, 이건 진짜 손해다. 카카오 로그인 페이지의 「카카오톡으로 로그인」을 누르면 앱으로 넘어갔다 오지만 손이 한 번 더 간다. 1.1에서 SDK로 바꾸는 이유가 이것이다.

## 3. 서버가 지금 하고 있는 일 (코드로 확인함)

```
등록된 제공자   구글 · 카카오        (네이버는 지도용이지 로그인이 아니다)
시작 주소       /oauth2/authorization/{provider}
성공하면        OAuth2LoginSuccessHandler:66-70
                「${oauth2.redirect-uri}?accessToken=…&refreshToken=…」로 돌려보낸다
                → 토큰이 **주소에 실려** 온다. 웹도 이 방식이다
사용자 찾기     ① findByProviderAndSocialId(provider, socialId)  있으면 그 계정
                ② 없으면 이메일로 찾아 있으면 **기존 계정에 소셜을 붙인다**(linkSocialAccount)
                ③ 그것도 없으면 새 계정. birthDate·addressSido는 null로 만든다
구글 전용 길    POST /api/auth/google  (idToken → JWT) · **이미 배포돼 있다**
                1.1에서 네이티브 SDK로 갈 때 쓴다. 이번 바퀴에는 안 쓴다
```

### 3-1. 이미 있는 결함 — 카카오 계정이 갈라진다

**②가 설계자의 의도인데 지금 통째로 안 돈다.**

```
콘솔        account_email = 「필수 동의 [수집]」 ✅ 켜져 있다 (비즈 앱도 됨)
서버 설정    kakao.scope = profile_nickname      ❌ 이메일이 빠져 있다
서버 문서    OAuth2_로그인_흐름.md:439
            scope=profile_nickname account_email  ← 문서엔 있다. 설정과 어긋난다
서버 코드    CustomOAuth2UserService.java:61
            email = "kakao_" + socialId + "@kakao.local"   ← 가짜 주소를 만든다
```

실측으로 확인했다 — `GET /profile/me`:

```json
{ "provider": "KAKAO", "email": "kakao_4692811908@kakao.local" }
```

가짜라 **아무와도 안 겹치니 ②가 절대 안 걸린다.** 같은 사람이 이메일 계정과 카카오 계정으로 갈린다. 웹에서도 지금 벌어지고 있는 일이다.

**고쳐도 깨질 게 없다**: 기존 카카오 계정은 ①에서 `socialId`로 찾으므로 로그인이 그대로 된다. 저장된 가짜 이메일만 남는다(`updateUserInfo`는 이름·닉네임만 갱신한다). 억지로 갈아끼우지 않는다 — 이미 그 이메일로 가입한 계정과 부딪힐 수 있다.

## 4. 흐름

```
앱 [카카오 간편 로그인]
      ↓  expo-web-browser로 연다
   https://cmarket-api.duckdns.org/oauth2/authorization/kakao?client=app
      ↓  카카오 로그인 → 동의 화면(닉네임·프로필사진·이메일)
   서버 OAuth2LoginSuccessHandler
      ↓  client=app 이면 앱 스킴으로
   cuddlemarket://oauth?accessToken=…&refreshToken=…
      ↓  브라우저 창이 저절로 닫히고 앱으로 돌아온다
앱: 토큰 저장(7바퀴 SecureStore 그대로) → GET /profile/me
      ↓
   needsSocialSignup(user) 이면 → 「추가 정보 입력」
   아니면 → 원래 있던 화면으로
```

### 4-1. `client=app` 깃발이 어떻게 살아남나

인가 요청을 보낸 뒤 카카오에 다녀오는 동안 서버는 **아무것도 기억하지 않는다**(STATELESS 세션). 그래서 깃발을 어딘가 맡겨야 한다.

**이미 있는 자리를 쓴다**: `HttpCookieOAuth2AuthorizationRequestRepository`가 인가 요청 정보를 쿠키에 담고 있다(세션 대신 쿠키를 쓰는 이유도 STATELESS라서다). 같은 방식으로 `client` 값을 쿠키 하나에 담고, 성공·실패 핸들러가 읽은 뒤 **지운다**.

```
① /oauth2/authorization/kakao?client=app
     → 쿠키에 client=app 을 심는다 (짧은 만료)
② 카카오 다녀옴
③ 성공·실패 핸들러가 쿠키를 읽는다
     app 이면 → cuddlemarket://oauth?…
     아니면   → 지금처럼 웹 주소
④ 쿠키를 지운다 (인가 요청 쿠키를 지우는 자리와 같은 곳)
```

### 4-2. ⚠️ 돌아갈 주소를 사용자가 정하게 두지 않는다

주소를 파라미터로 받아 그대로 쓰면 **남이 만든 주소로 토큰을 보내 버릴 수 있다**(오픈 리다이렉트). 앱이 보내는 것은 `client=app`이라는 **깃발 하나**뿐이고, 실제 주소는 서버 설정에 못 박는다. 앱이 고를 수 있는 것은 「웹이냐 앱이냐」 둘뿐이다.

### 4-3. 추가 정보를 왜 필수로 받나

앱에서 생년월일·거주지가 없어도 **막히는 기능은 없다**(확인함 — 마이 화면과 판매자 프로필에 지역이 안 보일 뿐이고, 생년월일은 가입 폼 말고는 안 쓴다).

그래도 웹과 같게 필수로 둔다:

- 흐름이 갈리면 나중에 두 벌을 유지하게 된다
- 중고거래에서 **판매자 지역은 신뢰 정보**다. 비면 상세 화면이 허전해진다
- 칸이 셋이라 이메일 가입(아홉 칸)에 비하면 훨씬 짧다

판정은 웹이 쓰던 규칙 그대로다: `!addressSido || !birthDate`

## 9. 완료 기준

**앱**

```
□ 로그인 화면에 「카카오 간편 로그인」·「구글 간편 로그인」이 웹과 같은 문구로 있다
□ 누르면 브라우저가 열리고, 끝나면 **저절로 닫히며 앱으로 돌아온다**
□ 처음 들어온 사람은 「추가 정보 입력」으로 간다
□ 추가 정보를 채우면 원래 있던 화면으로 돌아간다
□ 이미 다 채운 계정은 그 화면을 건너뛴다
□ 도중에 브라우저를 닫으면 조용히 로그인 화면에 머문다
□ 소셜로 로그인한 뒤 찜·상품 등록이 그대로 된다 (토큰이 제대로 저장됐나)
```

**서버**

```
□ 앱에서 시작하면 앱으로, 웹에서 시작하면 웹으로 돌아간다 (서로 안 섞인다)
□ 실패해도 앱으로 돌아온다
□ 카카오 로그인에서 **진짜 이메일**이 온다
□ 이메일 가입 계정과 같은 이메일로 카카오 로그인하면 **그 계정에 붙는다**
```

**게이트**

```
□ shared vitest · 앱 tsc·lint·jest · 웹 tsc·lint·vitest·build
```

## 12. 실기기 확인 결과 (2026-08-04)

**개발 빌드(dev client)로 확인했다.** 커스텀 스킴이 Expo Go에서 안 돌아 이번 바퀴부터 개발
빌드로 옮겼다([[project_mobile_sdk_pin]] 메모리 갱신). 서버는 배포 완료 상태.

### 통과

```
□ 카카오 로그인 (계정 선택 길) · 구글 로그인
□ 브라우저 → **앱 복귀** · 「추가 정보 입력」 → 저장 → 홈
□ 추가 정보 화면을 하드웨어 뒤로가기로 못 빠져나간다
□ 앱을 완전히 닫았다 켜도 로그인이 유지된다 (SecureStore)
□ 다시 로그인하면 추가 정보를 건너뛴다
□ 소셜 로그인 뒤 찜 · 상품 등록이 된다
□ 「이메일로 로그인」 → 성공 → **원래 보던 탭으로** (관문이 다시 안 뜬다)
□ 가입 → 자동 로그인 → 원래 자리 (관문이 다시 안 뜬다)
□ 웹 소셜 로그인 회귀 · 가입 화면 「생년월일」 이름표 회귀
```

**서버 로그로 확인한 것** — 이번 바퀴의 알맹이 셋이 한 줄에 다 있다:

```
OAuth2 로그인 성공: email=noonssub1004@nate.com, provider=KAKAO,
                   fromApp=true, target=cuddlemarket://oauth
  ① email=…@nate.com   진짜 이메일이 온다 (가짜 kakao_…@kakao.local 이 아니다)
  ② fromApp=true       깃발 쿠키가 살아남아 앱 스킴으로 갈랐다
  ③ 「기존 계정에 소셜 로그인 연동」  §3-1 결함이 풀렸다 — 이메일이 같은 계정에 붙는다
```

### ❌ 「카카오톡으로 로그인」은 안 된다

카카오 로그인 페이지의 노란 「카카오톡으로 로그인」을 누르면 **카카오톡 앱이 열리지만
인증 화면이 비어 있고**, 그대로 앱의 로그인 관문으로 돌아온다.

**우리 서버까지 오지도 않는다.** 시도한 시각(06:49Z)에 토큰 교환 기록이 없다 — 바로 앞
성공한 시도(06:47:45Z)는 남아 있다. 카카오 안(크롬 탭 → 카카오톡 웹뷰)에서 끊긴 것이고
우리 코드는 관여하지 않았다. 크롬 탭의 세션을 카카오톡 웹뷰가 못 이어받는 것으로 **추정**한다.

**1.0은 이대로 간다.** 계정 선택·비밀번호 길로 로그인되고, 카카오톡 앱-to-앱 인증은 원래
네이티브 SDK가 하는 일이다 — **1.1 SDK 전환에서 풀린다**(§2④).
