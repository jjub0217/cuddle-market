# 앱 커뮤니티 읽기 + 댓글 설계 (10바퀴)

> 2026-08-01 (토) 합의. 9바퀴(신고·차단, #805)가 끝난 다음 바퀴다.
> 앱만 하는 게 아니라 **웹 모바일도 같은 모양으로 맞춘다.**

## 0. 한 줄 요약

앱에 커뮤니티 탭을 만들어 **글을 읽고 댓글·답글을 달 수 있게** 한다. 게시글 신고도 넣는다.
그리고 **웹 모바일의 댓글 화면을 앱과 같은 모양으로** 고친다.

## 1. 왜 이번 바퀴인가

로드맵에서 10바퀴는 원래 소셜 로그인이었는데, 2026-08-01에 커뮤니티가 앞으로 왔다. 이걸 하면 딸려 풀리는 것이 셋이다.

```
1  알림의 커뮤니티 갈래가 앱 안에서 풀린다
   지금은 앱 안 브라우저로 웹을 연다 (mobile/lib/notifications.ts:146)
2  커뮤니티 글 신고를 넣을 수 있다
   9바퀴에서 「앱에 화면이 없어서」 미뤘고, COMMUNITY_REPORT_REASON도 그래서 shared에 안 올렸다
3  앱에 토스트 쓸 곳이 늘어난다
   웹 toastStore 규칙을 shared로 올릴 시점이 될 수 있다 (이번엔 안 한다)
```

## 2. 범위

**넣는 것**

```
앱   커뮤니티 탭 · 목록(질문/정보) · 상세(마크다운) · 댓글 화면 · 답글 · 게시글 신고
웹   모바일 댓글 화면을 앱과 같은 모양으로 · 댓글 스타일 통일 · 타입 정정
```

**빼는 것과 이유**

| 뺀 것 | 왜 |
|---|---|
| 검색 · 정렬 | 서버는 받지만 이번 바퀴 목표(읽기+댓글) 밖이다 |
| 댓글 좋아요 | **서버 API가 없다.** 당근·오늘의집엔 있지만 우리 서버엔 만들 수 없다 |
| 댓글 신고 | **서버 API가 없다.** 신고는 사용자·상품·게시글 셋뿐이다 |
| 글쓰기 · 수정 · 삭제 | 12바퀴(등록·수정·삭제)에서 상품과 함께 한다. 이미지 업로드가 같이 필요해서다 |
| 방금 쓴 댓글 강조 | 오늘의집엔 있지만 만들 것만 늘어난다 |
| 웹 데스크톱 배치 변경 | 데스크톱은 지금 배치가 맞다. 앱의 제약을 웹에 옮기지 않는다 |

**나중에 붙은 것 (2026-08-02)**: 차단이 커뮤니티 글과 상품 상세에도 먹게 하는 **백엔드 작업**이 이 바퀴에 들어왔다.

## 3. 서버가 주는 것 (실물로 확인함)

`~/Desktop/cmarket_api`의 `CommunityController.java`와 DTO를 직접 열어 확인했다.

```
목록      GET  /api/community/posts?boardType=QUESTION|INFO&page&size&searchType&keyword&sortBy
상세      GET  /api/community/posts/{postId}
댓글      GET  /api/community/posts/{postId}/comments        → { comments: [...] }
답글      GET  /api/community/comments/{commentId}/replies   → { comments: [...] }
등록      POST /api/community/posts/{postId}/comments        { content, parentId? }   로그인 필요
삭제      DELETE /api/community/comments/{commentId}                                  작성자만
글 신고   POST /api/reports/community-posts/{postId}          로그인 필요
사람 신고 POST /api/reports/users/{authorId}                  9바퀴에서 이미 씀
```

### 3-1. 반드시 알아야 할 서버 사실 넷

9바퀴에서 「다른 API가 이러니 이것도 그렇겠지」로 틀렸다. 이번엔 실물로 재서 못 박는다.

**① `commentCount`는 부모 + 답글 합계다**

```
글 36   commentCount = 7
        GET /posts/36/comments  →  부모 댓글 2개
        그중 답글이 4개 + 1개  →  2 + 5 = 7
```
웹 화면에 「댓글 7」이라고 뜨는데 댓글이 둘만 보이던 것이 이 때문이다.

**② 답글은 깊이를 안 나누고 평평하게 온다**

```
GET /comments/34/replies
  id=54  depth 2  parentId=34   "ddd"
  id=55  depth 3  parentId=54   "@협주 ㅇㅇㅇㅇㅇㅇ"   ← 54에 단 답글인데
  id=56  depth 3  parentId=54   "@협주 ㅇㅁㄴㅇㅁㅇ"   ← 같은 목록에 나란히 온다
  id=57  depth 2  parentId=34   "ㅇㄹㄴㅇㅇㅁㄴㅇ"
```

부모 댓글 하나 아래의 **모든 답글이 깊이 상관없이 한 줄로** 온다. 그래서 화면에서도 들여쓰기는 한 겹뿐이고, **누구에게 단 답글인지는 `@멘션`으로만 알 수 있다.**

**③ 댓글 목록에는 페이지가 없다** — 한 번에 전부 온다. 목록(글)은 페이지가 있다.

**④ 댓글 신고 · 좋아요 API가 없다** — `ReportController`에 있는 것은 `/users/{id}` · `/products/{id}` · `/community-posts/{postId}` 셋뿐이다.

### 3-2. 실측한 비용

```
글 28개 중 댓글이 달린 글    5개 (나머지 23개는 0개)
가장 많은 글(id 36)          부모 2개 + 답글 5개
답글 있는 부모 댓글          글당 1~2개
요청 하나당                  ~50ms
답글을 나란히 다 부를 때      +50ms 한 번치 (요청은 늘지만 시간은 거의 안 는다)
```

이 수치가 「답글을 처음부터 펼친다」는 결정의 근거다.

### 3-3. 응답 타입은 서버 DTO에서 새로 쓴다

웹 `src/types/community.ts`가 서버와 어긋난 곳이 셋이다. 웹 타입을 그대로 앱에 옮기지 않는다.

| 웹 타입 | 서버 실제 | 어떻게 |
|---|---|---|
| `CommunityItem.searchType: string` (필수) | 목록 DTO에 **없다**. 검색할 때 **보내는** 값이다 (`"title"`·`"title_content"`·`"writer"`) | 지운다 |
| `CommunityItem.isModified` | 목록 DTO에만 있고 상세 DTO엔 없다 | 목록에만 둔다 |
| `Comment.authorId: string` | 서버는 `Long` | `number`로 |

`authorId`는 웹이 지금 `Number(comment.authorId)`로 두 곳에서 되돌리고 있다(`CommentItem.tsx:48`·`:83`). 타입을 고치면 그 변환도 없어진다.

### 4-2. 왜 이 배치인가

**상세와 댓글을 나눈 이유**는 탭바다.

```
당근·오늘의집             우리 앱을 그대로 두면
┌──────────┐          ┌──────────┐
│ 댓글들     │          │ 댓글들     │
├──────────┤          ├──────────┤
│ 입력창     │          │ 입력창     │  ← 두 겹이 된다
└──────────┘          ├──────────┤
                       │ 홈 커뮤 마이│
   두 앱은 이 화면에    └──────────┘
   탭바가 없다
```

상품 상세는 2바퀴에서 「탭바 유지」로 정했다. 그 규칙을 깨지 않으려면 **댓글만 별도 화면으로 빼고 그 화면에서 탭바를 숨기는 것**이 맞다.

**답글 쓰기를 제자리에서 하는 이유**는 맥락 유지다. 당근은 답글쓰기를 누르면 화면이 통째로 갈리고, 오늘의집은 키보드 위에 입력 띠만 올라온다. 우리는 오늘의집 쪽을 고른다 — 답글을 읽던 자리가 눈앞에 남는다.

### 4-3. 댓글·답글 규칙 여덟

| 규칙 | 내용 |
|---|---|
| 답글은 늘 펼침 | 화면을 열 때 `hasChildren`인 부모마다 답글을 나란히 부른다. 접기 버튼 없음 |
| 답글은 한 겹만 | 서버가 평평하게 주므로 들여쓰기도 한 겹. 답글의 답글도 같은 자리 |
| 멘션 | 답글 쓸 때 입력칸에 `@닉네임 `을 미리 채운다. 지울 수 있다. 표시할 땐 맨 앞 `@단어`만 색 |
| 답글 대상 | 부모에 달면 `parentId`=부모, 답글에 달면 `parentId`=그 답글 (웹과 같다) |
| ⋮ 메뉴 | 내 것 → 「삭제」 · 남의 것 → 「이 사람 신고하기」(9바퀴 시트·신고 화면 그대로) |
| 삭제 | 확인창(9바퀴 `confirm-dialog`) → 성공하면 토스트 "댓글이 삭제되었어요." |
| 등록 | 성공하면 입력칸을 비우고 목록을 새로 받는다 |
| 게스트 | 읽기는 된다. 입력칸을 누르면 로그인 화면 (9바퀴 방식) |

### 4-5. 마크다운

`react-native-marked`(8.1.1, 2026-07-13 갱신)로 그린다. 조건이 앱과 맞는다 — `react-native >= 0.76`(우리는 0.81.5) · `react-native-svg >= 12.3`(우리는 15.12.1, 이미 있다).

웹 `MdPreview.tsx`가 정한 모양을 그대로 옮긴다.

```
h1 h2 h3      2xl / xl / lg · 굵게
p             15px · 문단 사이 12px
ul ol         왼쪽 들여쓰기 20px · 점 / 숫자
a             파란색 밑줄 → 눌러 앱 밖 브라우저로
code          회색 배경 · 모서리 둥글게

img           가로 꽉 채움 · 모서리 둥글게 · 비율 유지
```

**⚠️ 미검증** — 이 라이브러리가 React 19 · Expo 54에서 실제로 도는지는 설치해봐야 안다. 계획서 첫 단계를 「설치하고 글 하나 그려보기」로 두어, 안 되면 거기서 바로 **직접 만들기 안**(웹 도구모음이 만드는 7가지만 처리)으로 갈아탄다.

**⚠️ 이미지를 두 번 그리지 말 것** — 본문 마크다운 안에 `![](url)`로 들어 있고, 상세 응답의 `imageUrls`에도 같은 것이 들어온다(웹 목록이 본문에서 정규식으로 썸네일을 뽑는 이유다: `PostListItemResponse.java:20`). **본문만 그린다.** 구현 전 실물로 한 번 더 확인한다.

## 5. 웹 과제 (앱과 분리해서 먼저)

| 번호 | 무엇 | 어디 |
|---|---|---|
| W-1 | 답글 쓰기를 제자리로 (모바일) | `ReplyOverlay.tsx` 삭제 · `CommentList.tsx:222~246` 삭제 · 인라인 폼의 `hidden md:block` 제거 |
| W-2 | 답글을 처음부터 펼침 (웹 전체) | `openRepliesCommentId` 하나 → 여럿. 「답글 N개」/「답글 접기」 버튼 제거 |
| W-3 | 모바일에서 댓글을 별도 페이지로 | 새 경로 `/community/[id]/[name]/comments` · 상세의 댓글 섹션에 `hidden md:block` · 모바일엔 「댓글 7 ›」 링크 |
| W-4 | 댓글 스타일 통일 | 아래 표 |
| W-5 | 신고 사유를 shared로 | `COMMUNITY_REPORT_REASON` 5개를 `@cuddle/shared`로 |
| W-6 | 타입 정정 | §3-3의 셋 |
| W-7 | 멘션 떼는 로직을 shared로 | `renderContentWithMention`의 판별 부분 |

**W-1로 코드가 줄어든다.** 오버레이를 지우면 `history.pushState`로 뒤로가기를 잡던 장치도 같이 사라진다.

**W-3은 모바일만이다.** 데스크톱에서 그 주소로 바로 들어와도 그냥 보이게 둔다(막지 않는다 — 막으면 만들 것만 늘어난다).

**W-4 스타일 값** (개발자도구로 직접 맞춰본 값. `md:` 분기를 없애 모바일·데스크톱을 한 벌로 둔다)

| 자리 | 지금 (모바일 / 데스크톱) | 바뀜 |
|---|---|---|
| 닉네임 `CommentItem.tsx:82` | `text-[13px] md:text-base` → 13 / 16px | `text-sm leading-none` (14px) |
| 본문 `:87` | 클래스 없음(상속) → 16px | `text-[15px] leading-snug` |
| 멘션 `:18` | `text-sm md:text-base` → 14 / 16px | `text-sm` (14px) |
| 답글 상자 `:67` | `px-2 py-3 md:px-4.5 md:py-4.5` → 8·12 / 18·18px | `p-[14px]` |

> 본문에 `leading-none`(줄 간격 1)을 쓰지 않는다. 시험한 답글이 한 줄이라 표가 안 났을 뿐, 두 줄로 넘어가면 줄끼리 붙어 읽기 어렵다. `leading-snug`(1.375)가 지금보다 좁으면서 안 붙는다.

**W-7이 중요한 이유** — 멘션 떼는 로직이 웹·앱 양쪽에 생긴다. `@cuddle/shared`에 올리면 **shared의 vitest 하나로 양쪽이 덮인다.** 웹에 러너가 없어도, 앱 Jest를 안 돌려도 덮인다. 9바퀴에 신고 사유·차단 문구를 올린 것과 같은 방식이다.

## 7. 테스트

러너가 **둘** 있다. 웹만 없고, `#799`가 끝나면 웹에도 생긴다.

```
mobile/           Jest (jest-expo)     앱 화면·로직
packages/shared/  vitest               웹·앱 공용 로직 — 지금 20개, 200ms
src/ (웹)         없음                 #799로 vitest + RTL을 넣는다
```

> **지금 게이트에 shared 테스트가 빠져 있다.** 9바퀴 게이트도 앱 Jest와 웹 빌드만 돌렸다.
> 이번에 `pnpm --filter @cuddle/shared test`를 게이트에 넣는다.

**덮는 것 — shared (vitest)**

```
멘션 떼어내기      "@협주 내용" → { mention, rest }
                   "@" 없는 글 · "@"만 있는 글 · 본문 중간의 @ (안 떼야 함)
신고 사유          COMMUNITY_REPORT_REASON 5개가 서버 enum과 같은지
```

**덮는 것 — 앱 (`mobile/lib/community.test.ts`)**

```
응답 껍질 벗기기      { data: { comments } } · { data: { content, hasNext } }
                      ← 실제 서버 응답을 그대로 붙여넣어 만든다 (DTO 실물 기준)
commentCount 의미     부모+답글 합계라는 것을 못 박는 테스트
답글 채우기           부모 목록 + 답글 목록을 화면에 줄 모양으로
```

**안 덮는 것 (사람이 봐야 함)** — 9바퀴에 「테스트 154개가 다 초록인데 화면은 비어 있던」 일이 있었다. 무엇을 안 덮는지도 적어둔다.

```
마크다운이 실제로 그려지는지         실기기로
키보드 위 입력창이 안 가려지는지
탭바가 숨었다 다시 나오는지
본문 이미지가 두 번 안 나오는지
```

**게이트**

```
공용   pnpm --filter @cuddle/shared test           ← 이번에 게이트에 넣는다
앱     cd mobile && npx tsc --noEmit && npx expo lint && npx jest
웹     npx tsc --noEmit && pnpm build              (저장소 루트에서!)
       바뀐 파일만 npx eslint
```
> `pnpm lint`는 이제 게이트다(`#788`에서 오류를 다 없앴다). `pnpm gate`가 `tsc → lint → vitest → build` 순으로 돈다. 경고는 36건에서 못 늘게 잠겨 있다.

**웹에도 러너가 생겼다** (`#799`, vitest + RTL). 스펙을 쓸 때는 없어서 「사람이 봐야 함」으로 미뤄 둔 것 중 일부를 시험으로 덮을 수 있다 — 계획서 Task 3·5에 넣었다.

## 8. 미리 짚는 함정

| 함정 | 대처 |
|---|---|
| **화면을 한 스택에만 두면 탭이 튄다** (9바퀴) | 작성자 프로필 화면이 지금 `(home)`·`(my)` 둘에 있다. `(community)`에도 둬야 한다 — 세 번째 사본 |
| **탭바 숨기기** | Expo 54 문서를 확인하고 정한다. 돌아왔을 때 다시 나와야 한다. 추측하지 않는다 |
| **키보드와 하단 입력창** | `KeyboardAvoidingView`는 iOS·안드로이드 동작이 다르다. 실기기로 본다 |
| **토스트가 입력창을 덮는다** | 9바퀴에 토스트 높이를 `insets.bottom + 72`로 못 박았다. 이 화면은 탭바 대신 입력창이 있어 값이 다르다 |
| **`useBottomTabBarHeight()`는 탭 화면 안에서만 돈다** (9바퀴) | 탭바를 숨긴 화면에서 부르면 값이 맞지 않는다 |
| **본문 이미지 중복** | `imageUrls`를 따로 그리지 않는다 (§4-5) |
| **`cd mobile` 뒤 저장소 루트 명령** | `pnpm build`·`git add docs/…`가 실패한다. 9바퀴에 3번 걸렸다 |
| **Tailwind v4 티셔츠 크기** | `max-w-3xl` 같은 것은 48px로 풀린다. `max-w-170`·`max-w-7xl`을 쓴다 |

## 9. 완료 기준

**웹**

```
□ 모바일에서 「답글 달기」를 눌러도 화면이 안 바뀐다 (댓글 밑에 폼이 열린다)
□ 답글이 처음부터 펼쳐져 있다 (웹 전체 · 접기 버튼 없음)
□ 모바일 상세엔 「댓글 7 ›」 줄만 있고, 누르면 댓글 페이지로 간다
□ 데스크톱은 지금처럼 상세 안에 댓글이 다 있다
□ 댓글 글자 크기·답글 상자 여백이 새 값이다 (14 / 15 / 14px · 패딩 14px)
□ 두 줄 넘는 답글의 줄이 서로 붙지 않는다
```

**앱**

```
□ 탭바에 커뮤니티가 있고 눌러 목록이 뜬다 (질문/정보 두 갈래 · 무한스크롤)
□ 글을 누르면 상세가 뜨고 마크다운이 웹과 같은 모양으로 그려진다
□ 본문 이미지가 한 번만 나온다
□ 작성자 아바타를 누르면 프로필로 간다 · 탭이 안 튄다
□ 상세 ⋮ → 게시글 신고가 접수된다 · 내 글엔 ⋮ 가 없다
□ 「댓글 7 ›」을 누르면 댓글 화면이 뜬다 (탭바 숨김 · 하단 입력창)
□ 답글이 처음부터 펼쳐져 있다
□ 「답글 달기」를 누르면 화면이 안 바뀌고 「협주님에게 답글 남기는 중」 띠가 뜬다
□ 입력칸에 @닉네임이 채워져 있고 지울 수 있다
□ 댓글·답글을 등록하면 목록에 바로 보인다
□ 내 댓글 ⋮ → 삭제 → 확인창 → 토스트 "댓글이 삭제되었어요."
□ 남의 댓글 ⋮ → 이 사람 신고하기 → 9바퀴 신고 화면
□ 게스트가 입력칸을 누르면 로그인 화면이 뜬다 · 읽기는 된다
□ 알림의 커뮤니티 갈래가 앱 안 화면으로 열린다 (웹 브라우저로 안 나간다)
```

**게이트**

```
□ shared vitest (멘션·신고 사유)
□ 앱 tsc · lint · jest
□ 웹 tsc · build · 바뀐 파일 eslint
```
