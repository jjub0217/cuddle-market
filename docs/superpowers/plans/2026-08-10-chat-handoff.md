### 막혔던 원인 — NULL 문자

**RN 의 WebSocket 이 STOMP 프레임 끝의 NULL 문자를 흘렸다.**
서버(Spring)는 「메시지가 아직 안 끝났다」고 보고 버퍼에 담아 둔 채 기다린다 —
**오류도, 서버 로그도, 연결 끊김도 없다.** 그래서 밖에서는 완전한 침묵으로만 보였다.

```ts
// mobile/app/stomp-lab.tsx
forceBinaryWSFrames: true,         // 이 한 줄이 답이었다
appendMissingNULLonIncoming: true, // 받는 쪽 보호
```

**토큰은 처음부터 멀쩡했다.** 앞 세션의 「토큰 만료」 의심은 원인이 아니었다.

### 어떻게 갈랐나 — 폰만 봐서는 못 가른다

맥에서 같은 서버에 **직접** 세 가지를 보내고, EC2 로그에 무엇이 찍히는지 봤다.

```
텍스트 + NULL    → 서버 로그에 찍힘 ✅
NULL 없음        → 완전 침묵      ❌   ← 폰의 증상과 똑같다
바이너리 + NULL  → 서버 로그에 찍힘 ✅   ← 그래서 이걸 쓴다
```

같은 방법이 필요하면 `node` 로 `ws` 를 직접 열어 프레임을 손으로 만들면 된다
(`CONNECT\naccept-version:1.2\n\n\0`). 앞뒤 계층을 다 걷어내야 어디서 사라지는지 보인다.

## 서버 로그 보는 법 — 도커가 아니다

앞 세션이 `docker logs` 라고 적어 놨는데 **틀렸다.** EC2 에는 `java -jar` 로 떠 있고
`docker` 명령 자체가 없다. 자세한 건 저장소 루트 `CLAUDE.md` 「백엔드 저장소」에 옮겨 적었다.

```bash
tail -f -n 0 /home/ec2-user/cmarket_api/app.log
```

⚠️ 로그 시각은 **UTC** 다. 실험 화면의 시각도 UTC라 그대로 견줄 수 있다.

인터셉터가 돌기만 하면 아래 셋 중 하나는 **반드시** 찍힌다
(`StompChannelInterceptor.java` 134·140·156행). 그래서 **아무것도 안 찍히는 것 자체가 단서**다 —
프레임이 서버의 파서까지 도달하지 못했다는 뜻이다.

```
WebSocket 연결 성공: email=…
WebSocket 연결 실패: 유효하지 않은 토큰
WebSocket 연결 실패: Authorization 헤더 없음
```

## 여기까지 알아낸 것 (다시 조사하지 말 것)

### 웹은 이렇게 돈다

```
연결   SockJS + @stomp/stompjs · 재연결 5초 · 토큰은 connectHeaders
구독   /user/queue/chat · /user/queue/chat-room-list · /user/queue/errors
발행   /app/chat/message
REST   POST /chat/rooms · GET /chat/rooms
       GET /chat/rooms/{id}/messages · DELETE /chat/rooms/{id}
```

### 앱은 SockJS 를 못 쓴다

`sockjs-client` 가 XHR·쿠키 같은 브라우저 API 를 전제한다. SockJS 엔드포인트의
`/websocket` 경로도 **SockJS 프레이밍을 기대**해서 순수 STOMP 프레임에 무응답이다(실측).

그래서 백엔드에 **순수 WebSocket 엔드포인트를 하나 더** 등록했다(04a95bb, 배포됨).
같은 경로에 둘을 등록할 수 있어 웹은 영향받지 않는다.

```
/ws-stomp        순수 WebSocket   101 응답 확인   ← 앱
/ws-stomp/info   SockJS           200 그대로      ← 웹
```

### ⚠️ 출처를 `*` 로 열지 않았다 — 되돌리지 말 것

Spring 은 **Origin 헤더가 없는 요청(앱 같은 비브라우저)은 검사 대상으로 안 본다.**
그래서 웹과 같은 목록 그대로도 앱이 붙는다. 세 경우를 직접 붙여 확인했다.

```
Origin 없음(앱)      → 열림
evil.example.com     → 403      ← * 로 열면 이게 통과하게 된다
*.vercel.app         → 열림
```

처음에 `*` 로 열려고 했는데 **사용자가 「위험하지 않나요」라고 짚어 줘서** 고쳤다.

### 서버 DTO 에 탈퇴 여부가 없다

```
ChatRoomListItemResponse      opponentId · opponentNickname · lastMessage · unreadCount
ChatMessageListItemResponse   senderId · senderNickname · isBlocked · blockReason · isMine
ChatRoomResponse              sellerNickname 만 (opponentId 조차 없다)
```

2026-08-04 결정: **상대가 탈퇴했으면 채팅창에 표시해야 한다.** 탈퇴는 소프트 삭제라
채팅방이 남는데, 표시가 없으면 「읽씹당했다」고 오해한다.
**판별을 닉네임 규칙(`탈퇴{id}`)에 기대면 안 된다** — 서버에 필드를 추가해야 한다.

### 앱에는 실시간이 하나도 없었다

알림도 「화면에 들어올 때마다 다시 조회」다(`app-header.tsx` 주석: 「SSE는 안 쓴다 — 설계 §3」).
채팅이 **연결 계층을 처음 놓는 바퀴**다.
