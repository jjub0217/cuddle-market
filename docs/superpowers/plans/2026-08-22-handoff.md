# §1. 판 나누기 — 이번에 왜 실패했나

## 원인은 하나였다: `TMUX` 가 비어 있었다

```
세션 앞부분   TMUX=/private/tmp/tmux-501/default,…   → Agent(name:) 로 판이 갈라졌다 (1개 → 4개)
세션 뒷부분   TMUX=없음                              → 같은 방식인데 백그라운드로만 돌았다
```

tmux 세션(`claude`)은 살아 있었는데 **클로드 프로세스가 그 안에 있지 않았다.** 중간에 세션이
갈리면서 밖으로 나왔고, 그 뒤로는 「판을 갈랐다」고 말했지만 실제로는 아니었다.

## 시작 전에 반드시 확인

```bash
echo "TMUX=${TMUX:-없음}"        # 비어 있으면 판이 절대 안 갈라진다. 여기서 멈춰라
tmux list-panes -t claude:0 | wc -l   # 지금 판 개수를 센다
```

⚠️ `tmux list-sessions` 로는 못 가른다. 세션이 살아 있어도 **내가 그 안에 없을 수 있다.**
   `$TMUX` 환경변수만이 답이다.

## 판을 가르는 법 (2026-08-06·08-20 에 확인)

```
Agent(name: '이름', subagent_type: 'general-purpose', prompt: …)
      ↑↑↑↑ **name 을 줘야** 팀원으로 떠서 판이 갈라진다. 없으면 백그라운드다
```

**띄운 직후 반드시 세어서 증명한다.**

```bash
tmux list-panes -t claude:0   # 판이 늘었는지 **같은 창**에서 센다
```

⚠️ `list-panes -a` 로 세지 마라 — 창마다 판 하나씩도 세서 「갈라졌다」로 착각한다.

## 안 되는 것들 (반복 금지)

```
① Agent(isolation:'worktree')   백그라운드로 돈다
② Agent(name 없이)              백그라운드로 돈다
③ tmux new-window               **창**이 생긴다. 한 번에 하나만 보인다
④ tmux new-session -s 다른이름   별도 세션이라 사용자 화면에 아예 안 보인다
⑤ tmux split-window "claude -p \"…\""   따옴표가 꼬여 판이 뜨자마자 죽는다
```

## 판을 쓸 때의 규칙

```
판은 **같은 트리**에 띄운다 (worktree 격리를 쓰면 판이 안 갈라진다)
판에게    git 금지(index.lock 충돌) · 「;」 대신 「&&」 · 맡은 파일만
게이트는  **리드가 한 번만** 돈다 (팬들이 동시에 돌리면 겹친다)
커밋은    전부 리드가 한다
확인      가른 뒤 claude:0 의 판 개수를 세어 증명한다
정리      끝나면 TaskStop
```

⚠️ **작업 트리 하나에 브랜치는 하나다.** 웹과 앱을 동시에 돌리면 한 브랜치에 섞여 PR 을 못
나눈다. 라운드를 나누거나 한 PR 에 이슈 여럿을 담아라.

# §4. 이번 세션에서 데인 것 — 다시 밟기 쉽다

## 게이트가 초록인데 화면이 깨져 있던 일이 **다섯 번**

```
앱  글자를 <Pressable> 로 감쌌다              → 꾹 누르기가 통째로 죽었다
앱  부모에 onStartShouldSetResponder 를 달았다 → 마찬가지로 죽었다
앱  훅에서 Keyboard.dismiss() 를 불렀다        → 입력칸 탭에 키보드가 올라오자마자 내려갔다
웹  「초점이 밖으로 나가면 데려온다」를 넣었다    → 초점이 한 자리에 갇혔다
웹  지도 목록의 층을 낮췄다                    → 네이버 저작권이 목록 위로 드러났다
```

**전부 눈으로만 보이는 자리였다.** 시험은 「속성이 붙었는가」까지만 지킨다.

## 서버 응답을 「비슷한 이름」으로 넘겨짚지 마라

탈퇴 사용자 프로필이 404 일 거라고 단정했는데 **401 이었다.**
다른 파일의 `USER_NOT_FOUND(404, …)` 를 보고 그렇게 믿었고, 실제로 이 코드가 쓰는 것은
`ErrorCode.USER_NOT_FOUND(401, …)` 였다(주석은 「사용자 관련 (404)」인데 값이 401이다).

→ **화면에 응답을 띄워 재보고 나서야 알았다.** 막히면 그렇게 재라.

## 사용자 지적을 옮겨 적을 때 바꾸지 마라

「**상품등록 단추의 패딩**」이라는 지적을 「목록 좌우 여백」으로 적어 이슈를 냈고,
팬이 그대로 고쳐 엉뚱한 것을 손봤다. 진짜 원인은 `h-fit` 이 `Button` 의 `h-9` 를 덮는 것이었다.

# §5. 이어받기 문서를 올리는 법 (2026-08-22 에 정했다)

**`develop` 에 직접 커밋하지 않는다.** 이슈 → 브랜치 → PR 로 올린다.

예전 이어받기 문서들은 `develop` 에 바로 들어갔는데(`724256f5`·`c894b432` 등 부모가 하나인
선형 커밋), 그건 **「기본 브랜치에 직접 커밋 금지」 규칙과 어긋난다.** 문서라도 같게 간다.

```bash
# 1) 이슈 (템플릿: docs-issue · 라벨 DOCS)
gh issue create --label DOCS --title "docs: 이어받기 문서를 남긴다 (YYYY-MM-DD)"
#    이번에 만든 것: #1006 (그 본문을 본떠 쓰면 된다)

# 2) 브랜치 — 종류/이슈번호--이름
git checkout develop && git pull --ff-only origin develop
git checkout -b docs/<번호>--handoff

# 3) 커밋 → 푸시 → PR (base 는 develop)
gh pr create --base develop --title "docs: …" --body "…"   # 본문에 `- Close #번호`
```

⚠️ **관련 이슈는 목록 항목(`- Close #번호`)으로 적는다.** 문단으로 적으면 깃허브가 제목을
   안 펼치고 번호만 보여준다.
