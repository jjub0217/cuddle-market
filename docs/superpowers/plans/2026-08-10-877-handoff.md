**차단은 이미 동작한다.** 배포된 순간부터 차단한 상대의 메시지가 안 온다 — 실시간·알림·목록·다시
열기까지 넷 다 막혀 있다. **남은 것은 「차단한 본인의 입력창을 잠그는 것」뿐**이고, 그건 화면의
친절이지 기능의 핵심이 아니다.

⚠️ 그래서 **급하지 않다.** 지금 상태로 두어도 조용히 사라지는 메시지가 없다 — 한 방향만 막기로
했기 때문이다(차단한 사람이 보내는 것은 그대로 간다).

## 서버가 주는 값 — 이것만 알면 된다

```
필드 이름   isOpponentBlocked   (내가 이 방의 상대를 차단했는가)

웹이 읽는 곳   GET /chat/rooms            → ChatRoomListItemResponse
앱이 읽는 곳   GET /chat/rooms/{id}/messages → ChatMessageListResponse
```

**왜 두 군데냐** — 웹의 채팅 화면은 목록과 방이 한 화면이라 목록에서 읽으면 되는데, 앱의 채팅방은
루트 화면이라 방 번호만 들고 들어온다. 각자 이미 부르는 응답에서 읽는 것이 요청을 안 늘리는 길이다.

## 웹에서 할 일

```
src/graphql/schema.ts       ChatRoom 에 isOpponentBlocked: Boolean
src/graphql/resolvers.ts    chatRooms 리졸버가 room 을 손으로 매핑한다(165~171행) — 거기에 더한다
ChattingPage.tsx            **조회 쿼리에 필드 추가** + 입력창 잠금
```

⚠️ **가장 걸리기 쉬운 곳은 조회 쿼리다.** 스키마에만 더하고 쿼리에 안 적으면 값이 늘 `undefined` 라
**조용히 안 잠긴다.** 오류도 안 난다. 오늘 `groupCount` 로 같은 함정을 겪었다 —
그때는 조회처가 셋이었다.

⚠️ **알림 목록과 달리 채팅 리졸버는 손으로 매핑한다.** `resolvers.ts:165~171` 에서 `chatRooms` 를
`.map()` 으로 새 객체를 만든다. 거기에 안 더하면 스키마·쿼리를 다 고쳐도 값이 안 온다.

잠글 자리는 `ChattingPage.tsx` 의 입력칸 묶음(291~329행 근처)이다. 입력칸·보내기 단추·사진 단추를
막고 그 자리에 안내를 그린다.

```
차단한 사용자입니다. 차단을 해제하면 다시 대화할 수 있어요.
```

⚠️ `BlockModal` 은 성공하면 `['userPage']` 만 무효화한다. 채팅 화면은 `['chatRooms']` 를 쓰므로
**차단해도 입력창이 바로 안 잠긴다.** `BlockModal` 을 고치기보다 채팅 화면이 자기 것을 다시 부르게
하는 쪽이 안전하다 — 그 창은 다른 화면 셋이 쓰고 있다.

## 두 계정으로 확인하는 법

```
A가 B를 차단한다 (웹은 채팅방 ⋮ · 앱은 상품 상세나 프로필)
  → A의 입력창이 잠긴다 · 안내가 보인다 · 방과 지난 대화는 그대로 있다   (웹·앱 둘 다)
B가 메시지를 보낸다
  → B 화면에는 보인다 (차단당한 걸 모른다 — 의도한 것)
  → A에게는 안 온다 · 알림도 안 온다 · A의 채팅 목록 마지막 메시지도 안 바뀐다
A가 방을 다시 연다
  → 차단 뒤에 온 B의 메시지가 안 보인다
  → **차단 전 대화는 그대로 보인다** ← 이게 안 보이면 잘못 만든 것이다
A가 차단을 푼다 (마이 → 차단 목록)
  → 다시 대화가 된다
```

⚠️ 앱에서 차단은 **상품 상세나 프로필**에서 한다 — 앱 채팅방에는 더보기 메뉴가 없다.
