## 계약

```tsx
<DropdownMenu isOpen onClose triggerRef label>
  <DropdownMenuItem onClick tone={'default'|'danger'} disabled>…</DropdownMenuItem>
</DropdownMenu>
```

`triggerRef` 는 **감싸는 상자가 아니라 단추 자신**의 ref 다. 자리 계산과 닫을 때 초점 되돌리기의 기준이다.

## 조각이 알아서 하는 것 — 소비자가 또 할 필요 없다

```
portal(body) + fixed        자르는 조상·transform 조상을 다 넘는다
화면 밖 방지                 maxHeight 를 늘 주고, 아래가 모자라면 **위로 뒤집는다**
data-overlay-above          겹친 ESC 규약(#1003). **이 조각 말고는 아무도 안 단다**
role=menu / menuitem        aria-label 은 label 인자로
바깥 누르기 · ESC · Tab 닫기  useOutsideClick
열 때 첫 항목 초점            ⚠️ aria-disabled 인 항목은 건너뛴다
닫을 때 ⋮ 로 초점 되돌리기
stopPropagation             <Link> 안에서 열려도 링크가 안 눌린다(#793). 단 **키는 안 막는다**
z-index                     Z_INDEX.MODAL. ⚠️ portal **감싸개에도** 준다(#869)
```

## ⚠️ 이 조각을 고칠 때 절대 깨뜨리면 안 되는 것

```
키 이벤트에 stopPropagation 금지     막으면 ESC 가 document 까지 못 가 안 닫힌다
preventDefault 를 「내가 먹었다」 표시로 쓰지 마라   위층 <dialog> 가 ESC 로 안 닫힌다(ui.ts:80~82)
ESC 는 **버블**로 들어야 한다        마이페이지 패널이 캡처를 쓴다(MyPage.tsx:479)
닫히면 노드가 DOM 에서 **사라져야** 한다   hidden 으로 숨기면 표식이 남아 패널이 영영 안 닫힌다
```

# §3. ⭐⭐ 오늘 가장 큰 배움 — **눈으로 잰 것이 다섯 번 이겼다**

게이트가 초록이고 시험이 다 통과해도 **실물이 다른 경우가 다섯 번** 있었다. 전부 사용자가 보거나 내가 크롬으로 재서 잡았다.

| # | 시험은 뭐라 했나 | 실물은 어땠나 | 어떻게 잡았나 |
|---|---|---|---|
| 1 | 초록 | 메뉴가 **화면 아래로 넘쳐 잘렸다** | 사용자가 스크린샷 |
| 2 | 초록 | 메뉴가 **채팅 사진에 덮였다** | 크롬 실측(스택 사슬) |
| 3 | 초록 | Tab 뒤 초점이 **⋮ 가 아니라 패널 「닫기」로** 갔다 | 크롬 실측 |
| 4 | 초록 | 목록이 **60% 지점에서 잘려** 보였다 | 사용자가 상품 등록하다 발견 |
| 5 | 초록 | 뱃지 문구가 **판매요청 상품에서 틀렸다** | 사용자가 「sm 은 왜 만드냐」고 물어서 |

**공통점: 셋은 「배치」, 둘은 「내가 안 찾아본 것」이었다.** jsdom 에는 배치가 없고, 안 찾아본 것은 시험이 잡아 줄 수가 없다.

## 그래서 지킬 것

```
⚠️ **「정말 그 조건이 만들어졌나」를 같이 재라.**
   sticky 검사에서 「알약이 y=64 에 머문다」만 봤는데, 판이 **아예 안 움직이고 있었다**
   (상품 2개라 700px 화면에 다 들어감). 「스크롤됐나」를 같이 안 쟀으면 거짓 통과였다
   → 검사에 **전제 조건 확인**을 늘 끼워라

⚠️ **마커 검증을 붙여라.** 오늘 네 번 썼고 네 번 다 값을 했다
   고친 한 줄만 빼고 다시 재서 **증상이 정확히 돌아오는지** 본다
   「고쳤다」가 아니라 「이것 때문이다」를 증명한다

⚠️ **재기 전에 「고쳤다」고 말하지 마라.** 잰 것과 안 잰 것을 갈라서 말할 것
```

# §4. 오늘 새로 안 함정들

## ① playwright 로 로그인 뒤 화면을 재려면 `domcontentloaded` 를 써라

```
❌ waitUntil: 'networkidle'   →  30초 타임아웃
   마이페이지·채팅이 **STOMP 웹소켓**을 열어 네트워크가 영영 조용해지지 않는다
✅ waitUntil: 'domcontentloaded' + waitForTimeout
```

## ② `position: sticky` 는 `z-index` 가 `auto` 여도 **스택 컨텍스트를 만든다**

채팅방 ⋮ 메뉴가 사진에 덮이던 원인이다.

```
ChattingPage.tsx:328
  <div className="sticky top-0 …">        ← 스택 컨텍스트를 만든다
    <ChatRoomInfo>
      <div className="absolute … z-50">   ← 이 z-50 은 그 안에서만 통한다

실측한 사슬
  메뉴 쪽   DIV.absolute z-50 → DIV.relative → DIV.sticky(z=auto) → SECTION
  덮은 쪽   IMG.object-cover  → DIV.relative → ───────────────────→ SECTION
                                                    ↑ 같은 SECTION 안에서 DOM 이 나중인 쪽이 이긴다
```

**#869 와 같은 종류다.** 「안쪽 z 를 아무리 올려도 감싸개가 앉은 자리를 못 벗어난다.」
→ portal 로 body 에 내보내면 없어진다.

## ③ `transform` 이 걸린 조상은 `position: fixed` 의 기준점이 된다

```
MyList.tsx:145  <Link className="… hover:-translate-y-1 …">
                              ↑ 마우스를 올리면 transform 이 생긴다
```

그 안에서 `fixed` 를 쓰면 마우스를 올렸다 뗄 때마다 메뉴가 튄다.
⚠️ **마우스가 없는 실기기에서는 안 나타나 데스크탑에서만 걸린다.**

## ④ `:focus-visible` — 마우스로 열면 초점 테두리가 **안 보이는 게 정상**이다

```
마우스로 열었을 때   activeElement = menuitem · focus-visible=false → outline: none
키보드로 열었을 때   activeElement = menuitem · focus-visible=true  → outline: auto 1px
```

「초점이 안 갔다」로 오해하기 쉽다. **초점 진입을 확인하려면 키보드(Tab → Enter)로 열어야 한다.**

## ⑤ `max-h-[60vh]` + `scrollbar-hide` = 「잘린 것처럼 보이는 스크롤」

```
MyPagePanel.tsx:203 (전)   productCount > 1 && 'scrollbar-hide max-h-[60vh] overflow-y-auto'
```

60vh 는 **화면의 60%** 다. 상품이 화면을 다 못 채워도 넘으면 자르고, 스크롤바까지 감춰서
**「마지막 카드가 잘렸다」로 보인다.** 게다가 모바일 전체화면 패널(`fixed inset-0 overflow-y-auto`)
안에 든 **겹친 스크롤 상자**였다. → `md:` 전용으로 바꿨다.

## ⑥ 스토리를 더하면 lint 경고가 는다 — 상한 31 이라 게이트가 막힌다

```
storybook/prefer-pascal-case          스토리 이름은 PascalCase. 한글 이름은 `name:` 으로
@typescript-eslint/no-unused-vars     안 쓰는 StoryFn 인자는 `() =>` 로
```

## ⚠️ 여기서 문서 하나가 틀린 것을 찾았다

```
로그          2026-08-23T04:35:52.267Z   ← Z. UTC 다
DB created_at 2026-08-23 13:35:10        ← 같은 순간인데 9시간 앞선다 = KST
JVM           -Duser.timezone 없음 → OS 를 따른다 → **UTC**
```

**JVM 은 UTC 인데 `created_at` 은 KST 로 저장된다.** JDBC 가 바꿔서 넣기 때문이다.

```
-Dspring.datasource.url=…?serverTimezone=Asia/Seoul
                          ↑ 이것 때문이다

created_at   LocalDateTime → 드라이버가 UTC→KST 로 옮겨 담는다  (+9)
view_date    LocalDate     → 날짜뿐이라 안 옮긴다              (그대로)
```

```
이 저장소 CLAUDE.md  「로그 시각은 UTC 다」                    ✅ 맞다
백엔드 주석          「저장된 createdAt 이 모두 UTC 다」        ❌ 틀렸다. KST 로 저장된다
                    (ViewLogServiceImpl.java:22)
```

⚠️ **로그(UTC)와 DB `created_at`(KST)을 나란히 놓고 디버깅하면 9시간 어긋난다.** 실제로 그것 때문에
멀쩡한 것을 버그로 볼 뻔했다. **백엔드 주석을 고치는 것이 남은 일이다**(§7).
