## ⭐ 오늘 가장 크게 배운 것 — **가르기 전에 겹치는 파일을 재라**

사용자가 「이 넷은 파일이 안 겹칠 것 같으니 판 넷으로」라고 했는데, **재보니 아니었다.**

```
Home.tsx                ① 판매중(질의가 여기)   ③ 세부필터 기본값   ← 겹침
ProductsSection.tsx     ① 판매중(화면 거르기)   ④ 개수 헤더        ← 겹침
```

게다가 ④가 되살릴 줄이 이렇게 생겨서 **겹침이 아니라 의존**이었다.

```jsx
{/* <ProductListHeader totalElements={onlyOnSale ? visibleProducts.length : totalElements} /> */}
                                      ↑ ① 이 통째로 다시 쓰는 값
```

**재는 법** — 각 일감이 건드릴 이름을 grep 해서 파일 목록을 뽑고 겹치는지 본다.

```bash
grep -rn "onlyOnSale\|tradeStatus" src --include='*.tsx' | grep -v test | cut -d: -f1 | sort -u
grep -rn "ProductListHeader\|totalElements" src --include='*.tsx' | grep -v test | cut -d: -f1 | sort -u
```

## 진짜로 갈라지는 선

```
웹 src/…   ↔   앱 mobile/…        파일이 아예 안 겹친다. 오늘 이걸로 갈랐다
같은 이슈 안의 웹 작업 여럿          거의 겹친다. 한 판에서 순서대로
```

⚠️ **작업 트리 하나에 브랜치는 하나다.** 웹·앱을 같이 돌리면 한 브랜치에 섞이니 **한 PR 에
   이슈 여럿**을 담는다. 오늘 그렇게 했다(#1009·#1010·#1011 → PR #1012).

## 판을 쓸 때의 규칙

```
판에게    git 금지(index.lock 충돌) · 게이트 금지 · prettier 금지 · 「;」 대신 「&&」 · 맡은 파일만
게이트는  **리드가 한 번만** 돈다 (pnpm gate:all)
커밋은    전부 리드가 한다
확인      가른 뒤 판 개수를 세어 증명한다
정리      끝나면 TaskStop
```

⚠️ **판이 「idle」이라고 알려도 마지막 쓰기가 안 끝났을 수 있다.** 오늘 앱 판의 파일을 읽고
   「옛 문구를 썼다」고 판단했는데, **다시 읽으니 이미 고쳐져 있었다.** 고치기 전에 한 번 더 읽어라.

⚠️ **판에게 시킨 것이 도중에 바뀌면 `SendMessage` 로 알려라.** 오늘 개수 문구를 「전체 N개」에서

# §3. ⭐ 오늘 데인 것 — 둘 다 게이트가 초록이었다

## ① `act()` 가 경합을 가려 **시험이 거짓 초록**을 줬다

마이페이지 ESC 를 고치는데, 오버레이가 **세 겹**이었다.

```
패널  →  상품 메뉴 시트(⋮)  →  삭제 모달
셋이 다 ESC 를 듣는다. 한 번 눌렀는데 패널까지 닫혔다
```

**「열린 모달 이름을 나열」하는 가드로는 못 막는다.** 시트의 열림 상태(`isMoreMenuOpen`)는
`MyList` 안에 있어 `MyPage` 에서 볼 수가 없다. 그래서 상태가 아니라 **DOM 에 열린 것이 있는지**로
갈랐다(`dialog[open], [data-overlay-above]`).

그런데 그렇게 고쳐도 **여전히 패널이 닫혔다.** 왜인지 진짜 크롬으로 재서 알았다.

```
① window 캡처      표식 있음
② document(시트)   표식 있음   → 여기서 닫는다
   ···· 마이크로태스크 ····     ← 리액트가 여기서 시트를 DOM 에서 떼어낸다
③ window 버블      표식 없음   ← 여기에 달았다가 데였다
```

**리스너 하나가 끝날 때마다 마이크로태스크가 돈다.** 그래서 버블에 닿았을 땐 이미 없다.
→ **캡처 단계**(`addEventListener(..., true)`)로 옮겨야 한다.

⚠️⚠️ **이 경합은 jsdom 시험으로 못 잡는다.** `userEvent` 가 `act()` 로 감싸 리액트 갱신을 시험
끝까지 미루므로, **버블에서도 표식이 남아 있는 것처럼 보인다.** 내가 만든 탐침이 「표식 있음」
이라고 했고 **나는 그 거짓 초록을 믿고 「고쳤다」고 말했다.**

```
재는 법 — 진짜 크롬으로. 이미 깔린 크롬을 쓰면 새로 안 받아도 된다
  chromium.launch({ channel: 'chrome' })
```

시험이 **한국시간 자정이라는 「순간」**을 못박았는데, 구현은 그 순간을 **기기의 지역 날짜**로

```

TZ=Asia/Seoul   그 순간의 지역 날짜 7/31 → 생일 지남 → null      ✅
TZ=UTC          그 순간의 지역 날짜 7/30 → 생일 안 지남 → 문구   ❌
```

**개발자 맥이 한국시간이라 여태 안 드러났다.** 시험은 늘 초록이었다.

→ **시간대를 떼면 지역 시간으로 해석되어** 어느 기계에서나 「오늘은 7월 31일」이 된다.
  구현은 안 고쳤다 — 사용자 기기의 지역 시간으로 나이를 세는 것이 맞다. **틀린 것은 시험이었다.**

⚠️ **「내 기계에서 초록」은 「어디서나 초록」이 아니다.** 시각·지역·언어에 기대는 시험을 쓸 때는
   다른 시간대로도 돌려 봐라. 재는 법:

```bash
cd mobile && TZ=UTC npx jest                     # CI 와 같은 조건
TZ=America/New_York npx jest lib/…/x.test.ts     # 반대편도
```

⚠️ 앱 전체를 `TZ=UTC` 로 훑어 **다른 시간대 의존 시험은 없음**을 확인했다(2026-08-22).

## ⑦ ⭐ 초점을 옮기면 **뒤따르는 기본 동작의 대상이 바뀐다** (#1021)

좁은 폭에서 검색하면 **검색 오버레이가 안 닫혔다.** 검색 자체는 됐다 — 주소도 바뀌고 결과도
걸러졌다. **화면만 안 바뀐 것처럼** 보였다.

진짜 크롬으로 재서 알았다.

```
[탐침] onClose 불림 → setIsSearchOpen(false)   ← 닫는 것까지는 된다
[탐침] 돋보기 onClick. detail=0                 ← 그 직후 단추가 눌린다
[탐침] setIsSearchOpen(fn)                     ← 토글이라 다시 열린다
```

`detail=0` 은 **키보드가 만든 클릭**이다(진짜 마우스 클릭은 `1` 이었다).

```
① 엔터 → 오버레이를 닫는다
② useFocusTrap 이 초점을 **열었던 자리(헤더 돋보기 단추)로 되돌린다**
③ 엔터의 기본 동작이 그 단추를 누른다
④ 그 단추는 토글(!prev)이라 **다시 열린다**
```

→ 엔터 핸들러 맨 앞에서 `e.preventDefault()`.

⚠️ **초점 되돌리기는 안 고쳤다.** 그건 접근성상 맞는 동작이다. 고칠 곳은 「기본 동작」쪽이었다.

⚠️ **`CLAUDE.md` 의 「`setPointerCapture` 는 뒤따르는 click 의 대상을 바꾼다」와 같은 종류다.**
   초점·붙잡기처럼 **「대상을 정하는 것」을 건드리면 뒤따르는 동작이 엉뚱한 데로 간다.**

⚠️ **시험으로는 못 잡는다.** jsdom 에는 초점 되돌리기 뒤의 기본 동작이 없다.

⭐ **마커 검증** — `e.preventDefault()` 한 줄만 빼고 다시 재니 버그가 정확히 돌아왔다.
   「고쳤다」가 아니라 **「이것 때문이었다」**를 증명했다.

## ⑧ 같은 종류의 조건이 흩어져 있으면 **빠진 것이 안 보인다** (#1022)

차단한 사용자가 **넓은 폭에서는 2명, 좁은 폭에서는 0명**이었다. 좁은 폭에서는 요청이
아예 안 나갔다.

`MyPage.tsx` 의 세 질의를 **나란히 놓으니 바로 보였다.**

```js
구매내역  enabled: activeMyPageTab === 'tab-purchases' || effectiveNav === 'nav-dash'
찜한상품  enabled: activeMyPageTab === 'tab-wishlist'  || effectiveNav === 'nav-dash'
차단      enabled: activeMyPageTab === 'tab-blocked'          ← 뒤쪽이 없다
```

`activeMyPageTab` 은 **`?tab=` 에서만** 온다. 좁은 폭 주소는 `?panel=tab-blocked` 라 그 값이
`'tab-sales'` 로 떨어진다. 구매·찜은 `|| effectiveNav === 'nav-dash'` 라는 **탈출구**가 있어
좁은 폭에서도 돌았고, **차단만 그것이 없어서 이 하나만 빈 화면**이었다.

→ `|| mobilePanelTab === 'tab-blocked'` 를 더했다.

⚠️ `|| effectiveNav === 'nav-dash'` 로 붙이지 않았다. **대시보드에 차단 요약이 없어서**,
   그렇게 하면 마이페이지를 열기만 해도 안 쓰는 목록을 받아온다.

⚠️ **교훈은 「나란히 놓고 보라」다.** 흩어져 있으면 빠진 것이 안 보인다. 같은 종류의 조건을
   훑을 때는 `grep` 으로 **한 화면에 모아** 봐라.

```bash
grep -n "enabled:" src/features/my-page/MyPage.tsx
```
